# 验收清单

## 内容和来源

- 每位讲者独立 PPT，姓名来自已核实名单/封面，按用户命名。
- 用户给的时间点已定位到实际课件，边界前后、第一张封面、短暂结束页均回查。
- 按[选页规则](page-selection-and-dedup.md)核对动态代表状态与有效独立内容；每个删除候选有理由和代表页去向。动画合并后仍检查整套非相邻回翻，重复组只剩一个代表，每份只留一个结束页（用户另有要求除外）。
- 最终页码 → 稳定来源ID → 代表帧时间 → 裁切框 → 原始整帧可追溯；被合并状态映射到代表页，两套课件分别重编页码。工作日志私有保存，不进入备注。
- 所有页顺序正确；页数满足用户指定或已审核清单。普通截图提取没有固定应有页数，不能盲用之前任务的数量。
- 医学/技术关键文字、单位、正负号、指数、引用经过原图核对。原资料歧义与源缺失单独列明。

## 可见画面

全部页面全尺寸逐页查看，再用总览观察一致性。至少对封面、首中尾和存在问题的页面回看原始整帧。

- 没有会议摄像头、参会栏、正在共享提示、控制条、鼠标、会议计时器。
- 没有多余黑边、旧模板残片、颜色不一致的补丁或遮盖框边线。
- 报告日期、图例、坐标轴、图表年份、页脚、Logo 等有效内容完整。
- 文本框不溢出、不压图片，标题和正文无难看断行；数值/单位/括号保持可读。
- CT/病理/照片/曲线比例正确；没有为了 16:9 拉伸原 4:3 截图。
- 图片源自身模糊/截断的问题已定位，未假称恢复。模糊证据图不会被生成式内容代替。

## 文件验证

用当前宿主 PPT 验证器检查包结构、页数、比例、字体、文本溢出；这是正式交付的首选。附带补充检查：

```sh
python3 "$SKILL_DIR/scripts/audit_pptx.py" "$FINAL_PPTX" --expected-slides 12 --ratio 16:9 --require-empty-notes
```

`--expected-slides` 换成当前清单的页数。仅用户要求备注全空或新建提取稿时使用 `--require-empty-notes`。报告中的文字命中仅检查原生文本，不会识别图片中的残留。必须视觉检查。附带脚本不检查图片比例；图片裁切后的比例、分组/旋转对象由宿主工具及视觉验收确认，不能用画布比例通过推断全部图片无失真。

- 换底板、加首尾页后：`duplicate_entries` 和 `orphan_media` 为空，也就是旧底板媒体已经不在包里；`unused_layouts` 中只剩有意保留的版式；页码框数字等于实际页序。
- 回读**最终**文件，不把旧渲染、旧草稿当新版本验收。
- 复核源文件未意外修改；用户授权覆盖时保留必要备份并验证替换后文件。
- macOS 检查成品自身和成品目录的 Finder 隐藏标记；只清除意外隐藏的输出，不修改整个源目录。
- 有 PowerPoint/WPS 实际打开检查才说“已在 PowerPoint/WPS 检查”；其他渲染器通过不能冒充目标应用验证。
- 最终交付按用户参考目录保留当前版本、源素材与一份交接；用户要求清理时执行选页参考中的清理流程，待核对事项使用当前页码。临时脚本、截图、OCR、长日志不默认交付。

## 完成状态边界

可以说明“页面已重排，界面提示已清理，证据图保留原清晰度”。不能保证任何人都无法辨认来源，也不能把纯图片 PPT 描述为全文可编辑。若关键内容因遮挡缺失，应说明具体页码，不能以外观干净代替内容完整。

用户要求先交付时，可交付通过必要文件检查的阶段稿，明确尚未合入的修订和未完成的视觉验收。阶段稿交付不等于最终验收；整理文件名后也要在交接中保留此状态。
