# Google Flow 人物故事短片

尊重用户选择的产品、角色、声音和素材。先读取当前项目与已有成片，优先复用可用的镜头。不要把一次个案的模型、时长、音色或故事固化为所有项目的默认设置。

## 角色和分镜

- 三视图用于确认同一人物的脸、发型、发饰和服装；近景说话应有清晰正面人像参考。
- 角色实体的关联图片也可能占用模型的参考图名额。2026年10月的本次 Veo 3.1 Fast 实测最多三张视觉参考；以当前模型界面为准，不重复附加角色实体及其全部原图。
- 根据用户的目标时长规划镜头，再生成。一个镜头优先承载一个动作，记录景别、镜头运动、光线、人物和道具连续性，以及对白或旁白。
- 在 Flow 页面核对实际提交的逐镜提示，智能体可能简化长提示。尤其检查声音指令、角色身份、道具和灯光变化是否仍在实际提示中。
- 保留正式镜头的独立素材与可编辑场景，使用“作品_序号_动作”命名。区分场景原始时长与剪辑后成片时长。
- 已有镜头的组装不需要重新生成。本次 Flow 聊天智能体不能直接组装场景，但场景编辑器可以添加和排序片段；遇到此限制使用可用的 UI 操作。

## 中文声音

先确定声音方案和角色对白，再批量生成。声音好听的短样片应保留并标注用途。

- Veo 原生音频与画面一起生成，可产生人物对白和嘴型。声音没有可验证的预设名称时，不把它说成某个命名音色。
- Flow 角色语音库中的自定义语音预览可用台词和风格生成音频。本次用 Sulafat 生成了可下载 WAV；这不意味着 Flow 聊天智能体有独立音频生成工具。能力需以当前 UI 和实际文件为证。
- 用户选择 Flow 内置声音时继续使用 Flow。记录预设、风格、原文、实际时长和来源；不要自行改用外部配音。
- 后期替换对白只改变声音，保留原嘴型，不等于重新生成嘴型或克隆原样片声音。核对开口、停顿和结束位置；对白变长或逐字口型不符时，需重新生成支持该对白的画面或使用用户授权的同步功能。

## 避免人声重叠

读 [references/audio-workflow.md](references/audio-workflow.md)，在后期换声、加旁白或修复叠声时使用。

原生成视频的音轨可能含有声音，不能仅因标为环境声就与配音相加。若用新的人声替换原声，应完全排除原视频音轨。需要环境声或音乐时，另用已确认没有人声的素材，并单独管理。

`scripts/build_voice_track.py` 接收包含总时长及配音文件开始时间的 JSON，生成一条声轨，在实际样本区间重叠时拒绝输出。它不生成声音，也不重新生成嘴型。可同时复制已有视频并仅映射新声轨，避免保留原声。依赖 Python、NumPy 和 FFmpeg；先确认依赖可用，按本机网络规则处理必要的下载。

## 验证与交付

检查视频时长、实际宽高、帧率、音轨数、完整解码、字幕和关键帧。声轨数为一并不能单独证明没有叠声，还要检查混音来源及人声实际时间段。技术检查不能替代试听、逐字发音及逐帧嘴型核验；如无法试听，准确说明限制。

本地后期完成的成片与 Flow 中的原始场景分别标注，不能声称本地成片已同步到云端。文件上传工具的访问范围拒绝不能通过其他渠道绕过。

## 素材整理

按用户授权清理已被替代的成片、确认废弃的试作及字节一致的重复下载。保留最终成片、角色参考图、正式分镜、声音原件、字幕、制作清单和可运行的重建方法。不要把未纳入当前影片的历史项目素材视为废弃。

删除前核对依赖。若重建脚本读取待删除的旧成片，先改为从正式镜头与声音原件重建并验证。清理使用明确文件清单，记录原路径、原因、大小、哈希与去向；本地移至系统废纸篓，Flow 移至回收站，除非用户另有指示。

当前 Flow 素材界面通过类型、名称、收藏和搜索组织。没有实际文件夹或跨项目移动控件时，不虚构文件夹或调用猜测的内部 API。使用当前可用的 UI 设置并验证保存结果。

延续翡翠旗袍女子或《归灯》时，读取 [references/returning-lamp.md](references/returning-lamp.md)；其他项目无需载入该个案。该文件含私人项目链接和本地路径，只保留在本机，不进入公开仓库；缺失时直接读取当前项目目录的制作清单。
