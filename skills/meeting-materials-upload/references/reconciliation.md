# 对账、替换、删除重建和审核状态

## 三种范围

区分页面当前项目全部记录、本次本地资料对应的目标会议、目标中发生变更的文件。历史出现过把用户自建的清单外会议算入任务进度、把文件数当成会议数、把顶部完成场次当成总数的错误。

全量接口取得每条记录的 `meetingId`、`meetingName`、`meetingNumber`、`startDate`、`meetingStatus`、`supportFileCheckStatus` 和附件字段。历史四栏字段为：

```text
finalMeetingAgendaUpload
signTable
paidServicePhoto
venuePhoto
```

这些字段历史值为 `✔️`，不是布尔 true。页面发布后重新验证格式。完整列表未加载、响应失败或过滤条件不明时，不能宣称“没有驳回/没有缺失”。空列表要用项目身份和已知存在的对照会议排查，不能作为批量新建/删除的唯一依据。

名称匹配先精确，再比较规范化项目名 + 日期时间 + 讲者文本；同项目可能同时存在有前缀和无前缀名称，已存在会议不用为了统一命名而重建。匹配多个候选时列歧义，不自动选第一条。不根据相似人脸确认身份。

## 状态口径

`meetingStatus`（计划、已提供支持文件、已执行）与 `supportFileCheckStatus`（审核/审批）是不同维度。文件数量、四个勾、会议业务状态不能代替审核状态。

| 当前审核状态或证据 | 处理 |
|---|---|
| 未审核所有支持文件 | 经授权可以替换指定文件；整场删除仍需删除范围授权 |
| 审批中 | 不进入“删除未审核会议”白名单 |
| 审批完成/已审核 | 沿用用户“保持不变”规则；有新的明确更正要求再处理其许可流程 |
| 明确驳回/退回 | 记录实际状态和原因；查询请求只报告，不擅自重提或改资料 |
| 列表缺失 | 先核实项目、命名差异、列表完整性、访问权限和外部改动，不直接标“已删除” |

确定缺失后，可用已捕获的记录查询请求查旧 ID，并用存在记录对照。404/NOT_FOUND 不能单独排除权限和字段错误；只有得到对应访问上下文中的明确证据时写“已删除”，否则写“当前查不到”。

## 最新版变更

按“场次键 + 文件类别 + 相对路径”比较旧/新文件哈希，输出旧有新无、新有旧无、同路径变更和未变四种情况。截图数量与涉及会议数量分别去重统计。

如需与旧 Excel 问题清单比较，先规范化场次和截图类型，列集合差异；“Excel 标过问题”不意味着新版仍有问题，哈希未变也不代替当前口径的图片复核。内容复核使用当前用户规则与审核 Skill，旧 NF/FE/FO 标签不是网站审批状态。

用户授权单文件替换时：记录旧文件 ID/key → 新 key 预签名和 PUT → 核验对象 → 精确删除旧登记 → 登记新文件 → 核对类别、卡片数和对象。中断时报告“新对象已上传但旧登记仍在/新登记未完成”等具体状态。旧对象是否清理单独按授权处理。

用户授权整场删除后重建时：使用下节。新建后的会议 ID 和编号会变化，每场需按新 ID 上传完整资料；不能只传变更截图，也不能把旧 ID 写入新 objectKey。审核完成的场次若被要求保持不变，其旧截图仍会保留，交付明确列出这类跳过项。

## 已验证的删除技术方法

删除方法名称在现有经验文档中没有固定记录；不要猜 `deleteMeeting` 等入口。可靠方法是从一条本次授权目标的页面删除动作捕获真实请求，再重放相同 action，仅替换会议目标 ID。

用户已授权手动/脚本删除时不重复要求确认；目标范围没有明确授权时先生成具体可复核的白名单，再请求范围决定。单条试删也是实际删除，必须属于授权范围，不制造测试记录。

1. 固化白名单：会议名、编号、旧 `recordId`、日期、所属项目、当前审核状态、本地完整资料。保存删除前全量列表和集合。
2. 执行前重拉列表，逐 ID 检查本项目、名称、日期和编号；仅 `supportFileCheckStatus` 为“未审核所有支持文件”的会议进入此次删除。审批中、审批完成和未知状态跳过；查不到的 ID 不重删。
3. 试点：最新快照定位目标“显示操作 → 删除”，执行并捕获 Network 请求。检查响应成功、目标消失、对照会议仍存在、非目标集合未改变。
4. 批量：在已登录页面同源 fetch 重放捕获 action，只替换业务 recordId；保持 class/method/会话编码/其它参数结构。串行、每次约 5–10 条，唯一请求标识，每条检查 action 和业务结果，失败停止。
5. 每批：重新拉列表，计算删除前后 ID 集合差异。确认消失者仅在白名单；出现非目标消失时暂停后续写入，排查外部操作和误删，不能直接归因给某方。
6. 超时：检查页面脚本结果和实时列表，再判断尚存 ID 的原因；禁止直接重放全批。保存每 ID 请求结果与确认时间，不保存认证秘密。

删除验收是计划删除 ID 与已确认消失 ID 相等，非目标没有未解释的消失。重建上传另做独立验收。整场删除可能影响审核关系且无法恢复旧编号，不以文件登记删除的经验承诺其可恢复性。

## 查询有没有被驳回

用新鲜全量列表按实际 `supportFileCheckStatus` 分组，保留原状态文本，检查驳回、退回、拒绝、审核不通过等当次实际值。若 API 用英文/代码值，核对页面展示或捕获的映射，不能只搜中文或凭字段名猜编码。

结果说明查询时间、项目全量/目标范围、各状态数量。命中记录列名称、编号、日期、记录链接，必要时打开详情读取可见的驳回原因。没有命中只能说明**当前查询范围没有显示驳回状态**，不能断言历史从未驳回；需查历史时另读可见审核记录。

页面 DOM 有 Shadow DOM：普通 `document.querySelectorAll('[role="row"]')` 曾返回 0，`textContent` 也曾读不到状态；不能把 0 当无会议。优先全量接口，其次新 snapshot/可读 body 文本和递归开放 shadow root 作为核对。超大 snapshot 要存文件或仅返回分组/命中行，避免截断漏掉中间记录。需要“实时状态”时重拉接口，不只读早先打开的页面缓存。

## 每次任务的归档与结论

任务目录保存：资料 manifest（含版本/哈希）、实时匹配清单、创建 ID 台账、分批对象清单、PUT 结果、登记结果、前后系统列表、差异和最终摘要。可复用认证与签名 URL 不出现在共享文档；私有运行数据不进入公开 Skill 仓库。

结果区分：上传完成、四栏登记齐全、审批完成、已删除、已重建、待处理。报告目标场数与文件/记录数，给出具体剩余缺口，避免只说“全部请求成功”。
