# 保持局域网地址稳定

## 先区分地址变化和 SSH 故障

旧命令连不上时，先把命令里的地址与被连接端当前物理 Wi-Fi/以太网地址比较。若 DHCP 地址已经变化，而 SSH 服务、监听仍正常，先交付使用新地址的命令。不能因旧 IP 超时就重装 OpenSSH、重建密钥或扩大防火墙范围。

Windows 在已确认的物理接口上检查，`$selectedIndex` 来自本次接口选择，不固定为某个索引或 WLAN：

```powershell
Get-NetIPConfiguration -InterfaceIndex $selectedIndex
Get-NetAdapter -InterfaceIndex $selectedIndex |
  Select-Object Name, InterfaceDescription, MacAddress, HardwareInterface
Get-NetIPInterface -InterfaceIndex $selectedIndex -AddressFamily IPv4 |
  Select-Object InterfaceAlias, Dhcp
```

从该接口取得当前地址、前缀、默认网关和有效 MAC。不要用 TUN、虚拟机或 VPN 网卡的信息绑定路由器。Mac 端按 macOS 参考确定真实物理接口及其当前身份。

## 优先由路由器保留 DHCP 地址

用户要求地址不再变化时，在当前路由器为选定设备做 DHCP 地址保留（有些界面叫“IP 和 MAC 地址绑定”），电脑继续使用 DHCP。优先保留当前已经分配给目标电脑、且没有绑定给其他设备的地址；用户指定其他地址时先核实可用性，不把旧 IP 当作仍然空闲。

这一设置属于特定路由器及 MAC 身份，不能保证换到其他 Wi-Fi 后仍获得相同 IP。笔记本经常换网时，不为方便 SSH 就把整张无线网卡改为手工静态 IPv4。若确需在电脑端设静态地址，先明确适用网络、地址规划、网关/DNS 和恢复 DHCP 的方式。

核对当前网络是否使用随机/私有 MAC，以及它是否随连接或时间轮换。绑定的是该网络实际使用的 MAC；轮换后可能不再匹配。按用户选择保持这个网络的设备身份稳定，不自动全局关闭随机硬件地址或其他隐私功能。

## 路由器操作

1. 使用当前物理接口的网关访问管理页，不把历史网关地址当作本次事实。需要设备登录密码时让用户在管理页输入，不在聊天索要、记录密码或会话令牌。
2. 找到 DHCP 地址保留列表，核对既有条目。写入前在本机私有位置记下目标条目的原状态（新建则记录“原先不存在”），以便仅撤回本次新增或修改。
3. 以网卡 MAC 为主要依据匹配设备名、当前 IP。设备下拉可能带出旧地址；异步加载完成后逐项核对，不能仅凭名称或预填值保存。MAC 的冒号/连字符、大小写可以不同，但字节必须一致。
4. 只新增或修改目标设备的绑定，保留其他设备条目。保持原有网关、DHCP 池、租期、DNS、DHCP 开关及安全规则；不要为本次绑定重启路由器、断开所有客户端或开放公网端口。
5. 保存后等待成功状态，刷新或重新打开同一页面，确认目标 IP、设备名和 MAC 仍正确存在。看到“正在保存”不算完成。

### 华为随行 WiFi 3 Pro 的已验证入口

已验证的菜单是“高级设置 → DHCP → IP 和 MAC 地址绑定列表 → ＋”。在对话框中选择目标设备，核对自动带出的 MAC，明确填写本次要保留的 IP，再保存。列表中可能已有其他电脑的条目，不能整表覆盖。其他固件或型号以实际界面为准。

设备选择框可能是只读下拉；用下拉选项/箭头操作，不强行向只读输入框填字。切页、弹窗、选择设备或报错后重新观察，等预填值稳定再核对。窗口较窄时适当滚动，保存结果截图应完整显示目标 IP、设备名和 MAC，截图只留本机，不提交公共技能仓库。

## 验证、边界与恢复

- 路由器：刷新后绑定条目仍存在，值与所选物理网卡一致。
- 被连接端：当前 IPv4 与保留地址一致、DHCP 仍启用、SSH 服务和预期端口正常。本机读取 SSH banner 不能证明另一台电脑能登录。
- 客户端：交付准确的 `ssh <用户>@<保留地址>`，有执行权限时从另一台电脑完成身份验证；否则明确“跨机登录待验证”。已有 SSH 别名按需更新对应 HostName。
- 若电脑当前地址已等于保留值，不为测试强制断网/续租。尚未实测 DHCP 续租、重连或路由器重启时，按证据说明边界。
- 恢复时只删除本次新增的绑定，或将本次修改的目标条目恢复原值；电脑继续 DHCP，不删其他设备条目，不重置路由器。
