# Mac 与 Windows 局域网互访

服务于用户的一台 Mac 和一台 Windows。先确定谁发起连接、谁接受连接；只有作为被连接端的电脑才需要 SSH 服务。双向访问分别配置、分别验收。文件双向上传下载通常只需一端提供 SFTP，不必为了传文件把两端都开成服务器。

本 skill 保存方法，不保存当前 IP、用户名、SSID、MAC 地址、公钥正文、私钥或路由器密码；真实设备截图只留本机。已有会话中的设备资料可以复用，但地址、网络类别和服务状态要实时检查。历史上 Windows 本机检查成功，不等于 Mac 已登录，也不证明反向连接已经配置。

## 先检查，再决定改什么

1. 从上下文确定连接方向与用途：终端命令或文件传输。仅在不清楚时询问，不重复确认已明确的授权。
2. 找到当前物理 Wi-Fi/以太网的地址、网关与网络类别。VPN/TUN、虚拟机网卡及 `198.18.0.0/15` 等测试地址不是默认的局域网目标；结合接口类型判断，不能只取第一个 IPv4。不要假定 Wi-Fi 总叫 WLAN 或 en0。
3. 确认两端网络是否可路由。同一 Wi-Fi 名称、同一地址前缀不足以证明互通；访客隔离、VLAN、休眠、VPN 路由可能影响连接。只探测用户指定的另一台设备，不扫描整个网段。
4. 根据角色读取对应参考：
   - [Windows 端配置](references/windows.md)：Windows 被连接、SSH 服务、管理员公钥位置、网络类型和防火墙。
   - [Mac 端配置](references/macos.md)：Mac 被连接、远程登录、账号权限；或 Mac 作为客户端查地址和密钥。
   - [连接验收与故障定位](references/connection.md)：换网、主机指纹、SSH 别名、SFTP、错误分层。
   - [保持局域网地址稳定](references/address-reservation.md)：旧 IP 失效、路由器 DHCP 地址保留、有效 MAC 核对、华为随行 WiFi 绑定与保存验证。
   - [远程命令与配置维护](references/remote-operations.md)：SSH 登录后执行 PowerShell/Python、UTF-8、私有备份和桌面会话边界。
   - [跨机同步 Clash 配置](references/clash-sync.md)：用户要求远程 Clash 与本机一致时，保留远端订阅、当前选择和出口守护，只同步约定部分；同时读取 `china-proxy`，涉及 Claude 时再读取 `claude-maintenance`。

已有连接报 `Permission denied`、用户不记得密码或私钥时，先按连接参考检查本机 SSH 配置、agent 与有上下文依据的非默认密钥。一次默认密钥认证失败不代表没有可用凭据，不因此重装服务。

旧 IP 无法连接时先查被连接端当前物理接口地址；地址变化且 SSH 仍正常时，交付新命令。用户希望 IP 保持不变时，按地址保留参考处理路由器绑定，电脑保留 DHCP；该绑定只保证对应路由器及设备身份下的分配。

Windows 可先运行只读助手（路径相对于本 skill）：

```powershell
powershell.exe -NoProfile -File ./scripts/inspect-windows.ps1
# 已经知道另一台电脑地址时，可添加单目标探测：
powershell.exe -NoProfile -File ./scripts/inspect-windows.ps1 -TargetHost <对方地址>
```

助手不安装、不提权、不改变网络或防火墙，不读取密钥正文。JSON 的 `errors` 表示检查失败或权限不足，不能把未知解释成“没有规则/没有服务”。`firewall_rule_scope` 提醒它只列出名称含 SSH 的规则，不能排除其他规则的影响。

## 变更范围

- 仅总结、检查或编写 skill 时不改变机器网络配置。用户已要求配置或修复时，继续完成已授权范围内的必要步骤。
- 修改 Windows 网络类别前需要知道当前网络可信。先前的确认只针对当时网络，不自动适用于新连接的公共 Wi-Fi。只改已核对的物理接口；域管理网络按管理策略处理。
- 复用现有安装、账号、密钥和明确选中的规则。写公钥前按密钥类型与数据去重，保留其他公钥；记录所修改配置的原值，以便有针对性恢复。
- 密码、私钥及密钥口令由用户在自己的电脑处理，不复制到对端、日志或 skill。只安装用户明确选定的公钥，不自动导入发现的所有公钥。
- 管理员权限由正常 UAC/sudo 流程取得。准备好具体脚本后再启动；区分“等待授权”“运行中”“失败”和“已验证”，不模拟点击安全授权提示。
- 同一组件安装或同一配置写入只运行一份任务，保留日志和实际状态。下载 100%、文件已存在、进程已启动都不代表安装完成。停滞时定位系统维护状态，不并行重跑安装，不擅自重启。
- 不把局域网请求扩展成路由器端口转发、开放公网 SSH、停用防火墙、禁用主机指纹检查或调整无关代理。若两端分处不同网络，先解释需要可达路由/VPN/组网，按用户后续选择处理。

## 完成标准

按证据分层报告：服务/监听状态 → 从另一台电脑连通 TCP → SSH 身份验证 → 用户要求的操作。只有前一层通过，不能宣称后一层成功。

登录验收使用只读命令，例如 `ssh <用户>@<地址> whoami`，核对返回的目标用户。没有另一端执行权限时，给出它应运行的准确命令，并标注“跨机登录待验证”。只有用户要求传文件时，才用约定目录与小测试文件验收 SFTP，核对结果后按约定清理。

交付当前可用命令、验证到哪一层、实际修改及剩余问题。设置 SSH 别名时只合并目标条目，不覆盖整个用户配置；DHCP 地址变化后重新检查并更新该条目。

已实测 Mac → Windows 的既有非默认密钥登录、远程只读命令，以及 Clash 多订阅节点同步与当前订阅出口核验。新装 SSH、Mac 作为服务器、反向登录和其他订阅切换后的联网按各次证据报告，不沿用本次结果。
