# Clash 分流、链式代理与持久化

## 来源与备份

查正在运行的客户端和内核，不只看一个静态 `config.yaml`。Clash Verge Rev 通常把订阅、局部扩展、全局扩展与 GUI 链式选择生成运行配置。

首次修改前核实并备份：

- 当前订阅身份及相关源配置；保留所有未识别的节点。
- rules / proxies / groups / merge 等实际参与生成的扩展。
- 当前生成配置与当前选择状态，供核对而非长期唯一写入点。
- 用户要求修改原生链式功能时，相关可视化持久状态；数据库存在时用一致性备份方式，不在应用写入时盲拷或手改它。

从应用支持目录、进程参数及 UI 发现真实路径。不要写死开发者用户名、订阅 UID、密码或 controller secret。凭据备份放私有、权限受限的位置，报告恢复方法，不复制进这个仓库。

## 规则顺序

规则按首次命中处理。典型目标“国内直连，其余海外；Claude 只走指定落地”可按下列逻辑组织，而非照抄未验证的组名：

1. **专用入口/专用域名** → 已确认的固定落地节点或无 DIRECT 的专用策略。Claude 常见域名为 `claude.ai`、`claude.com`、`anthropic.com`；通过实际连接补齐，不把这个列表当穷尽。
2. **现有局域网/私有地址及必要系统服务** → DIRECT，保留用户原有含义。和专用入口冲突时先说明，不悄悄放行专用流量。
3. **国内域名规则集** → DIRECT。
4. **国内 IP 规则集** → DIRECT，确认 `no-resolve` 等选项是否符合当前 DNS 模式。
5. **MATCH** → 用户指定的海外策略，不以 DIRECT 兜底。

专用域名应在国内 IP 判断之前，否则污染/错误解析可能把专用请求引入 DIRECT。若用户要求所有海外流量不自动直连，逐层确认兜底组及引用组没有 DIRECT/fallback；只有 Claude 要固定出口时，不替用户删除普通组的其他选择。

规则集来源：

- [pluwen/china-domain-allowlist](https://github.com/pluwen/china-domain-allowlist)：选与内核 `behavior` / `format` 兼容的实际文件。不能把 hosts、纯文本域名或完整仓库 URL 当作 YAML rule-provider。
- [Loyalsoldier/clash-rules 的 cncidr](https://github.com/Loyalsoldier/clash-rules/blob/release/cncidr.txt)：核对 raw 内容、payload 结构与 provider 类型。

记录来源、快照日期、规则数、缓存位置和更新方式。离线快照不会自己更新；远程更新也要有超时、来源校验与可恢复的上一份数据。导入规则集不等于正确命中，需用连接记录验证。

## DNS 和连接识别

- 国内 DNS 仅用于约定的国内域名；默认/海外域名与代理节点域名的解析路径分开设计。
- 核对 `nameserver-policy`、默认 nameserver、proxy-server-nameserver、bootstrap/default-nameserver、DNS hijack 和实际系统解析器。需要经代理的 DNS 请求也应经过正确线路。
- `respect-rules`、fake-IP、sniffer 及排除列表按当前内核支持配置。注意引导解析循环：前置节点还未解析时，不能要求仅通过该节点解析自己。
- fake-IP 和嗅探有助于保留域名，但不能保证每个协议都识别成功；只看到 IP 的请求会落到 IP/MATCH 规则。因此兜底及专用入口仍需安全设计。
- 不因为浏览器某次测试通过就声称所有 DNS/IPv6 路径正常。

## 原生链式代理

```text
客户端 → 订阅中的普通前置节点 → 用户指定的落地代理 → 目标服务
```

- 用户在可视化页面管理的链，不用后台脚本自动重写。首次连不上时分别查前置可达性、SOCKS5 地址/认证、`dialer-proxy` 关联和最终出口，不擅自把落地换成别的节点。
- 重要的是最终出口；前置可以按用户意愿更换，但不能无关联地“随意变换”。每次变更后确认链仍以正确落地结束，再测公网出口。
- 直接把 SOCKS5 落地并列放进订阅，不代表它具有链式前置。它可能无法从本地直连，节点延迟 timeout 与认证/链式关系需分别诊断。
- 不假设 GUI 支持策略组作为前置；有些版本只渲染实际节点。有些原生链式实现会先清除 `dialer-proxy` 再按界面选择重建，手写关系可能被下一次 UI 保存覆盖。按本机版本检查生成结果，不泛化为所有版本。
- 不认识的节点保留；不为固定出口复制一个永久专用前置，除非用户明确需要。不同订阅的普通前置名称可能不一样，切换时确认各自引用存在。
- 节点 TCP/延迟测试通过不等于落地出口正确；链式组显示名称也不是证据，运行关系与目标请求记录才是。

## 持久化验证与故障测试

分别检查当前订阅、另一份订阅、切回、重启后的规则与链；事先确认是否允许切换/重启，并提醒用户暂停敏感会话。全局扩展应由真实来源证明，不把一次生成 YAML 写入成功称为“所有订阅继承”。

验证清单：

- 国内网站命中国内域名/IP 规则并 DIRECT；局域网仍可访问。
- Claude 新请求命中固定落地，普通国外网站命中约定兜底。
- 无显式代理的终端请求由 TUN 接管；显式专用入口请求由该入口接管。
- 前置或落地不可用时，专用请求被阻断且没有换出口；国内访问仍符合要求。
- Clash 整体退出后再测。仅靠 Clash 规则一般无法约束客户端退出后恢复的系统路由；显式入口可使使用它的客户端报错，但这不是全机 kill switch。

故障测试前保存工作、记录所有原始选择，结束后恢复并复测。仅页面报错不够，结合连接记录判断；离线模拟不能替代完整实机测试。

## 恢复与维护

恢复修改过的源配置和必要选择，重新生成/加载后核对运行结果；单独恢复运行 YAML 很可能再次被覆盖。分清“恢复规则”“恢复链式选择”“恢复专用启动器”和“恢复登录数据”，不要整目录覆盖。

订阅更新后、换订阅后、换落地后和客户端升级后重新检查引用与出口。保留上一份规则集和明确的备份路径；任何落地 IP 变化需用户确认新的期望值，不从探针结果自动改白名单。
