# 医学公众号 Figure 设计约束

> 用途：约束医学公众号中的统计图、论文式 Figure、多面板图，以及这些 Figure 在长文中的插入节奏与中英文版本处理。它不是图片生成器，也不是医学知识库。
>
> 核心原则：**参考图提供复杂度与视觉语法，当前冻结稿提供内容，已核验来源提供数字；Figure 的位置由整篇文章的论证节奏决定。**

## 1. 三种输入必须分开

制作 Figure 前，把输入分成三类：

```text
current_article      当前已冻结/接近冻结的正文或最终 HTML
verified_sources     已核验论文、指南、官方来源及其中可追溯数据
visual_references    用户提供的论文图、公众号截图、Figure 样稿
```

职责不同：

- `current_article` 决定**画什么**；
- `verified_sources` 决定**数字和医学结论能不能画**；
- `visual_references` 只决定**复杂度、面板密度、图例/坐标/Caption 的视觉方式**。

禁止：

- 因为参考图有弦图、年龄分层、季节曲线，就在当前文章没有这些内容/数据时也照画；
- 从参考图复制医学数字、结论或 Reference，当作当前文章的证据；
- 为了让图“复杂”而补造未被正文和来源支持的数据。

一句话：

> **借复杂度，不借内容；借版式，不借证据。**

## 2. 先从当前文章反推 Figure 任务

在生成图片前，先从当前冻结稿/HTML 提取最值得视觉化的信息结构。优先候选：

```text
真实统计结果 / 风险差异
自然史 / 时间路径
风险分层
检查或诊疗路径之间的关系
不同检测回答的问题
研究设计 / 主要终点
证据对比
基因型 / 亚组分布
```

每张 Figure 建立一个最小内容契约：

```text
figure_goal          这张图帮助读者理解什么
source_claims        正文中哪些已核验结论支撑它
source_numbers       允许进入图中的真实数字
panels               A/B/C/D 各面板分别表达什么
must_not_infer       不允许模型自行推演的内容
caption_source       Figure caption 对应正文引用编号/文献
```

如果当前文章只能支持一个简单比较，就画简单统计图；不要为了追求论文感硬扩成四面板。

反过来，如果当前文章确实同时支持自然史、定量风险、风险分层、检查作用等多个互补维度，而用户又明确提供高复杂度论文 Figure 作为视觉参考，**不要把信息压缩成几个装饰图标和一张低信息密度卡片**。此时应把复杂度放在真实信息结构上，而不是用空白、卡通图标或大色块代替内容。

## 3. 复杂度分级

### Tier 1：单图统计图

适用：一个主要数据问题。

```text
bar / horizontal bar
line
forest plot
scatter
stacked bar
```

应包含：坐标、单位、真实数值、必要时 95% CI、图例、Figure caption。

### Tier 2：组合 Figure

适用：同一论点有 2 个互补维度。

例如：

```text
A. 基因型个体归因 / 风险
B. 累积归因 / 临床解释
```

### Tier 3：多面板科学 Figure

适用：当前文章本身包含多个互补信息结构，且每个 Panel 都有来源支持。

常见组合：

```text
A. 自然史 / 流程
B. 定量风险图
C. 风险分层矩阵
D. 检查/诊疗作用矩阵
```

或：

```text
A. 主要基因型分布
B. 分组贡献
C. 亚组/时间趋势
D. 临床解释
```

复杂度来自**信息维度与互补关系**，不是来自装饰元素数量。

### 复杂度纠偏

用户说“太简单”“不像论文 Figure”“信息密度不够”时，不要直接增加装饰。按以下顺序检查：

```text
1. 当前文章是否本来就有多个可独立成 Panel 的信息结构？
2. 是否把真实表格/风险层级/检查作用过度压缩掉了？
3. 是否因为追求“科普易读”把论文 Figure 误做成卡通信息图？
4. 是否可以通过坐标、矩阵、分组、Panel、真实数值标签提高信息密度？
```

只有文章与来源真的支持时才升级 Tier。**复杂度不能超过证据，但也不应无故低于文章本身的信息密度。**

## 4. 论文式视觉语法

用户提供论文 Figure 作为参考时，可借鉴：

```text
A / B / C / D 面板编号
白底
黑/深灰坐标与文字
克制的医学配色
细灰分隔线
清晰图例
真实数值标签
95% CI / n（来源支持时）
Figure caption
正文引用编号
```

不要把论文 Figure 改成卡通科普信息图；也不要为了“品牌感”给数据图加过多丝带、人物、3D、光效或装饰图标。

### Figure body 与文章说明分开

Figure 主体里只保留：

```text
Panel 标题
坐标 / 图例 / 必要标签
必要的短说明
用户明确要求时的 Figure caption
```

不要把正文导语、整段解释、来源介绍同时塞在图片顶部和底部。用户如果说“去掉顶部和底部文字”，通常指的是这些**文章级叙述**，不代表要删掉必要 Panel 标题、坐标或图例。

如果用户明确要求“论文里的 Figure”，底部可保留正式 `Figure 1.` / `图1.` Caption；如果是普通公众号内嵌图，Caption 也可以放在 HTML 中而不是烧进图片。

## 5. 数据完整性

硬约束：

- 图中所有医学数字必须能回到 `verified_sources`；
- 图像生成模型不得自行补数字、CI、样本量、时间范围或研究结论；
- 若来源只支持摘要层面的数字，不要虚构更细的年龄组/月份/亚组；
- 概念流程图没有可靠数字时可以不写数字；
- 不把人群归因/人群风险直接写成某个个体的预测值；
- 不把相关性画成确定因果；
- 同一 Figure 中若混合多个研究来源，Caption 必须说清楚，不伪装成单一研究图。

如果生成模型把 DOI、PMID、期刊名、作者写错，**不要把错误来源留在图片里**。优先让图片只承载图形和必要标签，正式来源由 HTML 图注和 References 管理。

对于“人群归因比例”这类指标，必须主动检查是否容易被读者误读成“阳性后的个体患病概率”。如有风险，应在 Figure 或紧邻正文中明确区分。

## 6. Figure 与正文的连接

成熟医学公众号不要把图孤立地插进去。单张 Figure 的基本结构仍然优先：

```text
正文先提出结论 / 数据
↓
Figure
↓
Figure caption（图片内或 HTML 内二选一为主）
↓
继续正文，只解释最重要 takeaway
```

图前正文回答“为什么现在看这张图”；图后不要把图里每个数再复述一遍。

### 6.1 多张高信息密度 Figure：先做全篇 placement map

当文章有 2 张及以上论文式 / 多面板 Figure 时，**不要机械地把每张图都紧跟在最早出现对应数字的段落后面**。先看整篇文章的论证弧线，再决定插入点。

推荐流程：

```text
1. 标出全文 2～4 个主要论证单元
2. 标出每张 Figure 的“最小支撑文字块”
3. 避免两张高密度 Figure 连续出现
4. 让 Figure 分布在不同论证阶段
5. 必要时连同最小支撑段落一起移动，而不是只移动图片
6. 用前向提示和桥接句修复移动后的衔接
```

按语义锚点定位：Figure 紧跟对应证据块或放在其风险分层/临床解释中，图前说明为什么看图，图后解释关键含义。通常让两张高密度图之间保留一个完整论证单元，避免连续多屏堆图。

不按页面百分比插图。用户偏好的 HPV 成品中，Figure 1 和 Figure 2 约在 19.8% 和 55.8%，这些只是特定屏宽下的观测值，不是目标位置。完整默认视觉基准见 [医荟她文章样式](layouts/yihui-article-style.md)。

### 6.2 Figure 移动时允许调整文字位置

Figure placement 可以反向影响正文结构。以下情况允许移动文字：

- 某个数据段只服务于后面的 Figure；
- 原位置放图会导致两张 Figure 过近；
- 把“数据 + Figure”作为一个证据单元后移，文章逻辑反而更顺；
- 某个解释段在风险分层 / 临床意义章节出现更自然。

移动时保持：

```text
前文：短前向提示，例如“相关归因构成见后文 Figure 2”
新位置：一条桥接句解释为什么现在讨论这组数据
Figure 前：最小必要证据段
Figure 后：一句最重要 takeaway
```

不要为了均匀分图而随意打散因果链，也不要让 Figure 脱离其最小证据上下文。

### 6.3 微信手机端适配

论文 Figure 放进公众号时，要按约 650～700px 正文宽度检查，而不是只看桌面大图。

高密度 Figure 优先：

```text
图片宽度 100%
尽量去掉额外左右缩进
避免厚重装饰边框
避免重复 Caption
保证关键坐标 / 数字 / Panel 标题缩小后仍可读
```

如果在这个宽度下核心文字不可读，应优先重新排版、减少冗余文字或拆 Figure；不要仅靠导出更高分辨率掩盖布局问题。

## 7. Caption 与 Reference 闭环

### Caption 语言

Caption 语言跟随**目标场景和用户要求**，不要硬编码：

```text
中文公众号 / 中文阅读场景 → 默认中文标签 + 中文“图1.” Caption
英文论文 / 用户明确要求英文版 → 英文标签 + “Figure 1.” Caption
需要中英双版本 → 用同一数据与版式分别重绘，不在单张图里堆两套长 Caption
```

之前常见的“英文 Figure caption + 中文图注”只是一种样稿视觉语法，**不是默认规范**。

### 避免重复 Caption

- Figure 图片底部已经带完整 Caption 时，HTML 不要再原样重复一遍；
- Figure 图片不带 Caption 时，由 HTML 负责 Caption / 来源说明；
- 如 HTML 仍需来源，可保留简短来源行，不必重复整段 Figure 描述。

### 数据来源 / 注释行

论文式 Figure 里只要出现了具体研究数据，必须显式决定“数据来源放在哪里”，不能只在正文 References 里隐含存在。

优先规则：

```text
整张 Figure 主要来自同一研究
→ 图底或紧邻 HTML 放一条简短“数据来源 / Source”说明

只有某个 Panel 使用某项研究的定量数据
→ 明确写“Panel B 数据来源于……”
→ 其余概念性 Panel 标明“基于本文引用资料整理 / conceptual summary”

多个 Panel 来自不同研究
→ 按 Panel 映射来源，不用一条来源冒充整张 Figure 的共同出处
```

来源说明可以简洁到“作者 + 期刊 + 年份 + 正文引用编号”，但作者、期刊、年份、DOI/PMID 只有核验后才能写入。用户明确要求“论文里的 Figure”时，底部通常应包含 **Caption + 数据来源/注释**；普通公众号内嵌图则可以把来源行放在 HTML 中。

特别注意：**混合 Figure 的来源归属要精确到 Panel。** 例如 B 面板的长期风险来自一项队列研究，而 A/C/D 是基于多来源整理的概念性总结，就不能写成“整图数据来源：该队列研究”。

如果 Caption 已经烧进图片，来源说明应与 Caption 作为同一底部信息区设计，HTML 不再重复整段；如果来源说明放在 HTML，则图片本身保持简洁。

### Reference 闭环检查

新增 Figure 时同步检查：

```text
[ ] 图前正文是否有对应 [n]
[ ] Figure caption 是否指向同一来源
[ ] References 是否包含该文献
[ ] 删除 Figure 后，是否还需要保留仅服务于该图的文献
[ ] DOI / PMID / 年份 / 期刊是否核验
```

不要为了“显得学术”保留正文完全没有使用的参考文献。

## 8. 中英文版本 / 本地化

论文式 Figure 的中英文转换，本质上是**同一数据图的本地化重绘**，不是一次普通图片翻译。

优先流程：

```text
1. 锁定原 Figure 的数据、Panel 结构、坐标与图例映射
2. 建立术语表（HPV、CIN3+、AF、hrHPV 等缩写哪些保留）
3. 用可控绘图 / 矢量 / HTML/SVG 方式重新渲染文字
4. 重新计算中文换行与表格列宽
5. 对照原 Figure 做逐项 QA
```

不要把“让图像生成模型把整张英文论文图改成中文”作为高精度数据 Figure 的首选流程。文本密集图中，生成模型可能：

- 交换图例与数据系列；
- 改写专业术语；
- 漏字或错字；
- 改动数字；
- 改变 Panel 逻辑或箭头方向；
- 把 Caption 内容和图内标签混在一起。

如果只是视觉重绘，生成模型可以辅助；但**数据、文字和图例映射必须由可控层锚定并复核**。

## 9. 生成 / 绘图工具路由

本文件不绑定某一种绘图工具，但要按任务类型路由。

### 普通概念插图

可使用文章插画工具 / image generation，提高视觉完成度。

### 统计图、论文式 Figure、文本密集多面板图

优先：

```text
可控 plotting / SVG / HTML / vector
→ 锁定数据与文字
→ 必要时再做视觉润色
```

这类任务**不应被“正文插图默认走 illustration generator”覆盖**。只要图里包含精确数字、多个 Panel、表格、坐标或大量专业文字，就把它视为 scientific figure，而不是普通 illustration。

- 精确数据图优先用可控绘图工具生成数据锚点；
- 需要更高视觉完成度时，可以基于数据锚点做视觉重绘；
- 如果使用图像生成模型，必须把允许出现的数据与标签明确写入输入，并在交付后复核；
- 生成模型适合提高版式和论文感，**不适合充当医学数据源，也不适合承担唯一的文本排版层**。

## 10. 生成前 QA

```text
[ ] 当前 Figure 的内容是否能从当前冻结稿直接解释？
[ ] 是否只是借鉴参考图的复杂度，而没有照搬参考图内容？
[ ] Figure 的复杂度是否与当前文章信息密度匹配，既没有硬扩也没有过度简化？
[ ] 每个 Panel 是否都有存在的理由？
[ ] 每个数字是否有来源？
[ ] 有没有为了复杂度发明年龄、月份、亚组或机制？
[ ] 人群归因 / 人群风险是否可能被误读成个体概率？
[ ] 图内是否避免写未经核验的 PMID/DOI/作者？
[ ] 图与正文的引用编号是否闭环？
[ ] 两张以上高密度 Figure 是否被均匀分配到不同论证阶段，而不是连续堆叠？
[ ] Figure 移动后，最小支撑段落、前向提示和桥接句是否仍然完整？
[ ] Caption 是放在图内还是 HTML 内？是否出现重复？
[ ] 具体研究数据是否有显式的数据来源/注释行？混合来源是否精确到 Panel？
[ ] Caption 语言是否符合目标场景，而不是默认英文？
[ ] 中英文版本是否逐项核对了数字、图例、Panel、箭头和专业术语？
[ ] 在约 650～700px 正文宽度下，关键文字是否仍可读？
```

最终标准不是“看起来像论文”，而是：

> **内容来自当前文章，数字来自真实来源，复杂度服务于理解，位置服务于阅读节奏，语言服务于目标读者。**
