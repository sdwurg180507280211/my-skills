# Claude 本地数据清理与恢复

清理用途是修复错误登录、配置冲突、失效缓存或按用户意愿删除历史，不是擦除服务器上的账号记录或保证解除设备关联。本流程优先 macOS；其他平台须按实际 CLI/App 存储和凭据管理器核实，不宣称已实测兼容。

## 一、只读审计与目标分类

先确认用户要的是清缓存、移除旧登录、删除历史，还是完整重置。用户已明确“整个历史都不要”时，纳入方案，不再强制保留历史；仍保留确认、备份和不可恢复性说明。

发现实际配置目录（默认 `~/.claude`，可能由 `CLAUDE_CONFIG_DIR` 改变）、CLI 入口、项目目录、专用启动器和 App。不要从正在运行进程打印完整 argv/environment，因为它们可能含令牌。先发现目录，再在该范围内按用途分类：

| 数据 | 发现线索，不是固定删除目标 | 默认处置 |
|---|---|---|
| 配置与扩展 | 用户/项目/托管 settings、可能存在的 `~/.claude.json`、skills、commands、agents、插件、hooks 配置或自定义脚本 | 保护；只改已确认冲突项 |
| 缓存和诊断 | 已确认的 cache/debug/logs 等实际目录；失败排障所需日志 | 可列为清理候选，先确认不含历史和必要证据 |
| 会话与项目数据 | 可能存在的 projects、transcripts、tasks、文件编辑历史、组织关联文件 | 明确授权后清理；不能归为“可随便删的缓存” |
| CLI 认证 | 官方登录状态、配置文件中可能存在的认证来源、macOS 钥匙串 | 与历史分开确认，优先官方退出流程 |
| 桌面 App 数据 | 实际 App 对应的 Application Support、Caches、容器目录 | 分开确认缓存与登录/会话；不能删除整个 Application Support |
| 浏览器数据 | 专用 Chrome profile 的登录状态与 Cookie；普通 Chrome profile | 不自动清理，更不能误动其他浏览器环境 |
| 专用联网实现 | wrapper、guard、网络 settings、OAuth helper、状态目录 | 默认保护，清历史不等于卸载网络保护 |

表中路径会随版本变化；不存在的项如实报告。hooks 不一定有独立目录，设置和外部脚本都可能承载它们；不能只备份一个 `hooks/` 就声称已保护。

已知旧 `org_id` 只能作为私下定位线索。在确认属于 Claude 的存储范围内搜索，只报告命中类别和数量，不输出标识、匹配内容或凭据。逐个确认文件用途、当前账号是否仍引用及是否共享；不能全盘搜索后“匹配到就删”。相同标识的存在不证明封禁原因。

## 二、计划、备份与当前确认

给出私有操作清单：规范化源路径、类型、大小/估计空间、动作、保留理由、备份目标、恢复方式。确认符号链接的指向，拒绝根目录/用户主目录/项目根等宽泛目标、未解析变量和重叠父子删除项。

原始问题明确涉及全部 `~/.claude` 时完整备份它及实际依赖配置；小范围修复备份受影响文件即可。完整重置时另外核对根目录配置、专用联网文件和技能软链接。不得递归跟随技能链接把整个技能仓库带入清理；备份链接本身，并单独记录外部目标，不修改目标。

- 在私有目录创建带时间戳的备份，目录权限 700、敏感备份 600；不要提交或上传。
- 保存文件清单并检查备份可读、必要文件数/校验和及可用空间。备份失败或目录仍被写入时不继续。
- 普通文件的备份不包含钥匙串；说明凭据删除后的恢复通常是重新官方登录，而非从文件备份“自动找回”。
- 先让用户保存工作并退出相关 CLI/App/后台会话，再检查是否仍有写入进程。不擅自 kill 或退出其他 Chrome。由另一个工具或终端执行，不能由正在使用待清目录的 Claude 自清理。
- 把实际清单交给用户当前确认，可约定 `CONFIRM` 对应这份清单；它不是全局授权口令。缓存、会话、钥匙串、App 登录、时区/标识等范围须分别明确。任何新增目标都重新确认。

## 三、仅执行确认范围

普通文件优先移至实际用户废纸篓中独立的时间戳目录，保留源路径→目标路径清单，不覆盖同名文件。不永久删除、不清空废纸篓。废纸篓不可写/跨卷移动失败时停止，或提出私有隔离目录方案并确认，不偷偷改成 `rm`。

移走文件前再次检查路径、符号链接和当前内容是否与清单一致；不跨共享目录、不跟随指向仓库的链接。不因“完全清理”删除 Node/Python、官方 CLI 二进制、Clash 订阅、浏览器全部数据或其他产品认证。

逐项记录成功/失败。失败时停在可恢复状态，不让重试扩大范围；后续应用重新生成文件不等于旧文件没有清理，也不能循环删除正在生成的数据。

## 四、钥匙串与登录状态

先通过官方 `/logout` 或当前版本的 `auth logout` 退出所选账号，这属于修改认证状态，仍需当前授权。再检查是否有需要单独处理的条目。

macOS 常见服务名是 `Claude Code-credentials`，但配置目录或客户端版本可能改变命名；服务名只是发现线索。核对条目的 service、所属客户端、用途和共享影响。不输出账户名、密码/令牌，不调用 `security ... -w`、`-g` 或全钥匙串 dump。只读存在性检查也可能触发系统权限提示，不能绕过。

确需删除时，对核实的单个条目单独说明影响并确认；不删除整个登录钥匙串、不对所有包含 Claude 的条目批量操作、不试图把解密凭据导出到聊天或备份文档。官方退出可能已移除条目，先复查，不把“未找到”当失败继续扩大目标。

App 退出、CLI 退出和浏览器退出不是同一操作。重新登录后仅脱敏核对认证方式和所选账号是否正确；账号内容留在本机，不要求用户贴邮箱、org_id 或回调 URL。

## 五、恢复与验收

恢复前停用仍在写入的对应客户端并取得必要确认。按操作清单恢复本次移走的文件；目标已被新会话生成时先保留新内容并比较，不整目录盲覆盖。凭据按官方流程重新登录，不能恢复旧组织访问资格或服务器记录。

验收清理目标消失/已更新，受保护的 skills/hooks/会话及配置仍可用，官方 CLI 与需要的 App 正常启动，认证模式正确，网络入口没有丢失。实际联网验证走 [客户端验收](clients-and-migration.md)。把清理事实与账号安全结论分开；不得以“没有搜到旧 org_id”证明账号不会被关联或封禁。
