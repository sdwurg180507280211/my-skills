# 页内动画、视频与整套去重

提取候选是录像的画面状态，交付页是课件的逻辑页面，两者不能直接一一等同。生成第一页草稿前确定选择规则；用户后来调整规则时，增量应用到当前文件。

## 1. 交付模式

- **独立课件整理版（默认）**：一个原课件页保留一个有代表性的完整状态；同一讲者无新增内容的回翻页只保留一次。扫描阶段仍保留所有候选，审核后再决定合并。
- **复现讲述过程**：用户明确要求逐步状态、回翻顺序或逐帧记录时，按该要求保留，并说明页数包含重复展示。不要擅自套用去重默认。
- **只检查重复**：列出当前文件名、实际页码、重复内容与判断依据，暂不改文件；用户要求处理时再执行。

把规则写入任务私有清单。已经确认的规则跨轮次持续有效；后续换底板、重新生成或换模型时也要应用，不能让旧候选重新变成独立页。

## 2. 如何选一页

| 画面变化 | 判断与选择 |
|---|---|
| 正文、表格、图片逐项出现 | 通常保留全部内容出现后的清晰状态；检查最后一帧是否有淡出、弹窗或遮挡 |
| 页内视频、动态CT或显微录像 | 保留一个清晰且有代表性的静态画面，不把每次切片变化拆成幻灯片；保留该页其他图像和标签 |
| 卡通、照片或示意图临时遮住正文 | 优先选择正文完整的无遮挡状态，不能机械保留时间最晚的一帧 |
| 后出现的图替换了前面的实质内容 | 回看转场，辨认是否同页动画；按用户的一页一图要求选代表状态，并记录被替换的独有内容，不能宣称全部动态信息均保留 |
| 相同标题、不同病例、日期、剂量、图表数据或解剖层面 | 属于独立内容，保留；标题相同、布局相同不足以认定重复 |
| 同一页反复出现、仅鼠标或会议时钟不同 | 整理版去重，优先选无遮挡且清晰的一次 |

页内动态和真正翻页的判定依据包括视频转场、源页码、固定文字与图框、图像是否连续变化，以及所有对象是否一同换页。相似度、持续时间或“都是CT”只用于筛选候选；不足以判断时回查源视频，不猜删。

## 3. 合并后再做一次全套去重

**局部动画合并和整套回翻去重是两项独立检查。** 不能只比较相邻页：`A → B → A → B` 中的重复会被相邻比较漏掉。

1. 从当前实际交付的PPT读取页面顺序。每位讲者单独比较全部页面；不同讲者使用同一张指南图不构成跨文件删页依据。
2. 先筛候选：比较正文文本、图片内容/裁切和页面预览。比较时可忽略已确认的页码框、会议计时器与鼠标；报告日期、图表坐标、标注和医学数值必须参与比较。不要把比对用的屏蔽操作写回成品。
3. 对候选成对看图，并核对关键内容。正文相同而证据图不同、题目相同而病例不同均不能合并。图片文件哈希不同也不代表内容不同，录像压缩、鼠标或应用重存会改变字节。
4. 给每组写明成员页、保留页、删除理由和来源标识。优先保留清晰、完整且在讲述结构中合适的一页，其余页映射到该代表页。
5. 检查首尾：原感谢页与新增标准感谢页只留一个。纯玫瑰、校园风景等结束装饰不必为保图另占一页；含实质结论、致谢名单或联系信息的末页要保留或完整纳入新的结束页。
6. 再查合并后的全部页面，确认每个重复组只剩一个代表，独立内容仍在，最终页数等于原页数减实际删除数。

截图提取版和浅色重排版有新增首页/结束页时，页码不一定只差1。用稳定的候选ID或源页面ID建立两套映射，再同步删除；不要盲套固定偏移。用户说“原版PPT”通常指提取版，交接中注明并非作者原始可编辑文件。

## 4. 对已有PPT增量删页

仅删页、重编页码时可使用宿主支持的窄范围OOXML编辑，保留已校对正文和证据图。先比对最新文件指纹；用户侧应用重存或手工修改后，以当前文件为输入，不重跑旧生成器覆盖。

- 实际顺序由 `ppt/presentation.xml` 的 `p:sldIdLst` 经 `ppt/_rels/presentation.xml.rels` 解析。`slide17.xml` 不等于第17页，应用保存后部件名可能全部重排。跨版本比较也按实际顺序/稳定内容标识，不能按部件名直接对照。
- 包内关系的 `/ppt/...` 是从包根开始，去掉前导 `/`；相对Target按关系所属部件目录解析。错误解析会把仍在用的版式或媒体当成无用文件删除。
- 删除已确认的页序项及其关系，处理自定义放映/分节/跳转等对已删页的引用。只清理确实失去所有引用的幻灯片、备注和媒体，共享母版、图片与主题保持可达。
- 页码优先按已知对象名定位，必要时结合页脚位置和纯数字内容。只更新页码对象，保留首页、结束页原本无页码的状态；正文的序号和数值不得全局替换。
- 保存到新文件。检查ZIP无重复条目、所有内部关系可解析、实际页序/页数、尺寸、备注及页码。对删页以外的保留内容做前后对比，医学图片字节和裁切保持不变。
- 做当前宿主的文件验证和回读；小范围删页可以复核受影响页并扫描全套顺序，无需重做OCR、重建排版或把全部图片重新编码。旧预览仅能辅助筛选，不能冒充最终文件渲染。

## 5. 交付与清理

用户要求先交付时，交付已通过必要文件检查的当前版本，并说明剩余问题、可编辑范围和实际验证边界；未合入的内容修订不能算进成品。不要为了生成新一轮全套排版继续拖延已经可交付的文件。

用户要求整理目录时：

1. 先查看指定参考目录的结构和命名。常见结构为根目录保留源视频、底板、海报、时间点和一份 `模型交接说明.md`；`原版PPT/` 与 `整理后/` 各保留每位讲者一份当前版本。只保留实际存在的输入，不从另一场会议复制缺失的模板凑结构。
2. 按实际交付清单、页数、哈希和修改时间确认最新文件。旧文件在最新版生成后又被用户编辑的，先保留并核对；不要按文件名里最大的版本号机械清理。
3. 交接写明当前文件名、页数/比例、完成状态、当前页码下的待核对事项、源定位、用户确认的选页规则和后续范围。文件名改为整洁名称不代表阶段稿已最终验收。
4. 若权威JSON含有未生成的新修订，明确“内容清单版本”与“已交付版本”的差异；保留续作所需信息。旧页码说明要转换到最新页码，不能只留下即将清走的对照表链接。
5. 将已核对的旧版PPT、截图、渲染、缓存、临时脚本和多轮重复说明移入废纸篓的本任务独立目录，记录恢复位置。不要清空废纸篓，不移动其他任务或源素材；网盘同步元数据不按临时文件随意处理。
6. 清理后核对保留文件的哈希、数量和可见性。交接在任务根目录，不能与工作目录一起清走；另存新版本时的备份与阶段日志不应长期堆满交付目录。
