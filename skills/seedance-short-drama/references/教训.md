# 短剧教训

每次生成（剧本定稿、构图预览、成片）交给用户之前，记下这次最弱的至多 3 处；开工前先读这里，计划里写明避开了哪几条。规则见 Mac `~/.claude/CLAUDE.md`「生成后自我复盘」：同一条第二次出现就升级进 SKILL.md 正文并从这里删掉，最多留 20 条。

格式：`日期·作品：不足 → 原因 → 下次怎么做`

- 2026-10-22·先听她说：做"多样性"方案时把主角放在病人夫妻身上，用户纠正"主题是这个医生"→ 没先确认系列主角是谁 → 改戏或扩成系列之前，先用一句话确认"这一集的主角是谁、观众跟着谁走"。
- 2026-10-22·先听她说：构图预览用了付费 Seedream → 没读生图网关说明 → 预览一律走免费 gpt-image 网关，付费生成先报价。
- 2026-10-23·一号难求第1集：把 DeepSeek 推断的拍摄限制（轮椅婴儿易崩、每画面不超过三张脸、竖屏难同框）当成定论转述，其中"三张脸"还是我自己写进审稿指令、没有依据的规矩 → 转述时没标出处，也没核对 → AI 反馈逐条标出处、交用户审批；没有实测依据的限制不写进审稿指令。
- 2026-10-23·一号难求：把旧项目的规矩（真实关、每段 12 秒）原样搬到新剧，用户问"谁定的"才发现出处和适用范围都不对 → 没核对规矩从哪来、管哪类片 → 新项目开工前列一遍要沿用的规矩，标出处和适用范围，请用户确认。
- 2026-10-23·一号难求：第一版人设只有属性和小道具（扣表、秒表），用户说"没点设计""市场上看不到成功先例" → 没用人物方法论 → 人物先写行动模型（信念、惯用策略、代价、盲区、想要而没得到），配角要有自己的目标和秘密、亲手造成转折；招牌找有成功先例的写法。
- 2026-10-23·一号难求：第 2 集默认拿现成的林悦夫妻剧本，用户说"没必要"→ 舍不得已写好的稿子（沉没成本）→ 每集内容按"病例照出主角当下处境"来选，现成稿子只进素材库。
- 2026-10-30·双刃手术刀第1集：把".gitignore 没挡住 `双刃手术刀/`"当待办挂了好几轮，其实仓库早有 `AI视频/短剧/*/第*/*` 规则 → 只看了 `git status` 里的 `??`，没有逐个查规则 → 说"没被忽略"之前，先用 `git status -uall -- <目录>` 和 `git check-ignore -v <文件>` 核实到具体文件。
- 2026-10-30·双刃手术刀第1集：分镜表 S14/S15 顺序和剧本相反，提示词按剧本写了，却没改回分镜表，一直拖到全集生成完才修 → 改提示词时只改了一处 → 剧本、分镜表、提示词三处任何一处改了镜头顺序或台词，当场同步另外两处，提交生成前按镜号逐条核对。
