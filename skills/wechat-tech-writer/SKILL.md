# 小团子Java技术公众号适配层

这是账号上下文和交付偏好，不是另一套 Writer。文章研究与写作交给 `content-research-writer`，配图交给 `canghe-article-illustrator`，HTML 交给 `canghe-markdown-to-html`，用户明确要求上传时再用 `canghe-post-to-wechat`。定位并完整读取当次所需上游的真实 `SKILL.md`，按其原生流程执行；缺依赖就说明安装方法，不自行实现 fallback 或修改上游。

## 账号与写作 Brief

- 目标账号是 **小团子Java**，读者包括用户的朋友。主要方向是软件推荐、下载与入门、AI 和开发工具的实际用法，优先“看完能做一件事”，不自动写成行业趋势或原理长文。
- 给 Writer 传递已知主题、读者、推荐或教程目标、篇幅、资料、样稿、视觉方案和下列事实边界。已有信息不重复问；用户要求直接成稿时连续完成上游流程。
- 用户说“推荐给朋友”时，采用自然、具体的分享口吻，说明为什么值得试、适合谁、第一步怎么做。允许基于已知设计作个人判断，但不能冒充真实使用经历。未实测就不写“用了一个月”“亲测更有效”或虚构朋友故事。
- 避免空泛背景、夸张安利和反复口号。按完整意思分段，局部强调关键判断，不把每句话拆成一段；也不把长段硬合成文字墙。这是账号偏好，不规定 Hook、章节数、段落模板或结尾格式。
- 用户要求“多写点”时，增加有用的操作细节、适用场景、选择依据和注意事项，不靠重复推荐理由或罗列未经核实的功能扩篇。用户当次要求优先。

## 软件事实边界

软件名称、开发者、官网/商店入口、系统与版本要求、功能和价格优先核对官方资料。区分免费下载、免费功能、试用、买断与订阅；未核实的价格、按钮位置或任务设置不要补造。动态信息标明核验时间或提醒以当前页面为准。

区分“官方描述”“作者建议”“实际测试”。概念图不是真实截图；没有界面依据时不画精确按钮或假 UI。真实截图优先使用用户有权使用的素材。安装、购买、授予权限或创建真实任务不因写教程而自动获授权。

## 用户选中的图库案例

用户给 Image Gallery 固定链接或完整方案时，实际读取该方案并保存在文章工作目录；不每个步骤重新读取当前默认覆盖选择。方案只提供视觉，不提供软件事实或发布授权。

用户没有指定方案时，技术号默认正文图和封面都使用内置案例 `canghe-article-editorial`（杂志信息图）：封面改为约 2.35:1 并重新留出中文标题区。该案例可直接从图库项目的 `wechat/styles.json` 按 ID 读取，样图在 `assets/style-previews/`，无需方案链接；不要改写图库默认方案，那是医学号在用的。

- 固定快照形如 `<图库站点>/image-gallery/api/recipes/<id>`，图库站点地址以用户给出的链接为准。图库及接口已要求登录，匿名请求会返回 401；在有登录文件的本机用图库项目的 `scripts/read-wechat-recipe.py --url <链接> --output <文章目录>/wechat-style-recipe.json` 读取，不把密码写进链接、命令参数或文章目录。无法登录时请用户提供完整方案文件。没有指定方案、需要读取库默认时才使用 `/image-gallery/api/recipe`；它不能代表浏览器尚未保存的临时选择。
- `styles.layout` 控制正文排版，读取 `instructions`、`css` 及存在时的 `template`、`componentDefinitions`，不把基础 CSS 当完整模板。若方案仍是医荟她模板，不自动迁移其品牌；用户已确认技术号用简洁排版时，仅沿用指定封面和正文案例。
- `styles.cover` 与 `styles.illustration` 分别控制封面、正文图。读取 `instructions`、可选 `prompt.text` 和 `preview`，保留所选具体案例的整体构图、布局、配色、材质、线条和文字层级，只替换本篇内容；不再自行拆成“画风＋另一种布局”混搭。
- 提示词已说明清楚时直接沿用；参考图用于明确复刻案例或核对整体设计，不另起炉灶。支持参考图输入时，将所选样图传给生图工具。`preview` 相对路径以站点的 `/image-gallery/` 为基准解析，不相对 `/api/recipes/<id>` 拼接。
- 仅 `prompt.exactGenerationPrompt=true` 才能称该样图完整生成记录已核实；否则沿用已有规则并说明来源边界，不保证生成像素相同。提示词中已经包含的原文不要重复拼接。
- 当前方案是排版、封面、正文案例三类；封面明确启用的 `dimensions` 覆盖其预设，正文不叠加历史独立布局或未启用细节。用户当次明确要求最高优先，例如本篇封面改成与正文同风格。
- 特定快照读失败时保留用户选择，尝试其提供的方案文件；不要静默换风格，也不要写服务器默认。

## 图文模式与扩图

图文模式让图表达一组主要信息，文字补充实际用法、背景或限制，不逐字抄图。根据内容安排图的位置和数量，不固定两张、六张、每段一张或每章一张；具体数量由用户当次要求优先。

扩图时先核对现有稿件、图片和所选案例，保留用户已认可的素材。新图服务于新增的有效内容，使用现有图作一致性参考；并列选择不画成因果或必经步骤。将本次完整提示词先保存到文章工作目录，再用可用的生图工具生成。沿用苍何的安排与记录，不新增状态机、Claim 系统或一套生图脚本。

公众号成品默认包含 **独立封面与正文配图**，两者单独核对；用户明确不要封面时跳过。封面默认约 2.35:1，单独设计标题安全区，不直接拉伸样图，也不默认拿首张正文图充当封面。封面与正文可以按方案使用不同案例，不能假定二者相同。

## HTML 与交付

用户给出文章目录时，将成品 HTML 放在其一级目录，图片可放 `imgs/`；不迁入仓库。扩写或重排已有成品前保留可恢复旧版，同步修改 Markdown 和 HTML，避免下次渲染恢复旧内容。提示词与所选方案留在当次工作目录，不固定要求一大套报告文件。

无指定排版时，使用本 Skill 的 [简洁技术主题](assets/themes/xiaotuanzi.css)：正文 16px、行高 1.85、段距 18px，资料区 12px。这只固化视觉参数，不固定文章结构，也不声称已确认的医学模板可以自动适配技术号。

通过苍何原生外部主题接口加载，不复制渲染器。先解析 `TECH_SKILL_DIR` 和 `CANGHE_HTML_SKILL_DIR` 为实际安装路径，在工作副本上运行：

```bash
MD_THEME_DIR="$TECH_SKILL_DIR/assets/themes" \
  bun "$CANGHE_HTML_SKILL_DIR/scripts/md/render.ts" \
  /path/to/article.md --theme xiaotuanzi
```

此入口已在本机安装版本验证；升级后复核接口。需要资料小字号时用 `sources` 类包裹资料区。测试版本的工作副本不带 YAML frontmatter，标题/作者/摘要另传给发布器；首个 H1 是文章标题。预览版加 `--keep-title` 保留一次标题，微信正文不重复 H1。若源稿没有文章标题，保留第一个正文小标题，不机械删除。

交付前检查最终 HTML 的实际字号、图文衔接、图片数量与顺序、中文图中文字、独立封面、外链，以及桌面和手机窄屏无溢出。教程还要核对列表序号、长代码和宽表格的实际显示，不能仅凭主题 CSS 宣称可读。说明实际交付的正文图数、封面和文件位置；只有生成图而未插进成品，不算图文完成。

## 账号与发布边界

默认只制作文章，不自动上传或群发。用户明确要求上传/发布时，按发布上游创建草稿；群发是另一个动作，需要当次明确授权。先用已有可信账号映射或管理后台身份确认目标 **小团子Java**，本次调用显式选定对应配置，并检查环境变量是否覆盖它；不能仅凭配置文件名或当前默认猜测。无法确认账号归属时保留本地成品并请求确认，不打印凭据。不得使用医荟她健康的凭据、Logo、声明或医学主题。

生成图保存本地 PNG/JPEG，引用发布器支持的路径，不将不支持的 base64 HTML 当上传输入。明确提供封面，并核对正文每张图的上传及真实草稿；取得草稿 ID 不代表图片完整，创建草稿不等于群发。无法检查真实草稿时只报告实际完成的本地或上传步骤。

本 Skill 不存 AppID/AppSecret、Token、服务器密钥、登录态、文章原稿或图片。新电脑需安装完整 Skill 目录、所需上游及其运行依赖；按实际安装路径加载主题，私有文章和发布配置另行迁移。单篇已验证效果不保证跨模型逐字相同或跨设备像素一致。
