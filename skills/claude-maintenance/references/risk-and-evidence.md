# 风险判断与素材筛选

用户可能以“防封”描述诉求。先理解为减少可控制的配置错误和不符合要求的使用，而不是接受账号免封承诺。平台完整风控未知，账号历史及服务器记录不能由本机清理消除。

## 将收集到的建议逐项分类

| 建议类别 | 技能采取的处理 |
|---|---|
| 查系统代理、shell、包管理器、Git 和 Claude 配置 | 采纳脱敏审计；非空不等于有问题，不原样输出 env/settings |
| 清理用户目录、App 支持目录和钥匙串 | 采纳明确目的和范围的清理流程；按当前版本发现，分别确认认证/历史/缓存 |
| 按旧组织标识查历史 | 仅在 Claude 存储范围内私下定位，逐项核实用途；不凭命中批量删或推断封禁原因 |
| 全备份、只读审计、保护 skills/hooks、时间戳废纸篓、当前 CONFIRM | 采纳并补上备份核验、链接边界、执行清单和恢复；不承诺钥匙串也可废纸篓恢复 |
| 让正在运行的 Claude 清理自己 | 不采用；先保存并退出对应进程，避免被写入和重建 |
| 代理变量/ANTHROPIC 变量一律清空 | 不采用；区分有意的专用代理、OAuth 与合法 API，只修当前冲突 |
| TUN 使应用无法察觉代理，系统代理为零就安全 | 无法据此得出结论；TUN 接管与系统代理可见性、服务资格是不同问题 |
| 改台北/新加坡时区或轮换本地 ID 就清除设备指纹 | 不作为防封措施执行；没有证据证明可消除关联或恢复资格。合法时间设置/官方故障恢复按单独明确任务处理 |
| 设备反复被封就已被标记，本机清理能“救回设备” | 个案/推测，不当作事实或成效承诺；先区分实际错误及官方账号通知 |
| 国内白名单之外全部海外即可覆盖所有检测 | 可用于用户要求的分流，但不证明所有应用、DNS/IPv6 和故障路径均受保护；服务商所在地推断不是保证 |
| 节点失效不换出口，手机/电脑一致 | 按用户要求核对实际路径，不假设一次测试覆盖所有设备；客户端整体退出另测 |

上表是对策略类别的原创归纳，不复制用户原文或第三方脚本。外部 `claude-cleanup` 链接是审查线索，不是当前授权或依赖；需要采用代码时先读实现、核对权限/许可证/版本和高风险副作用，不能直接下载执行或自称已验证。默认不需要安装外部清理器。

## 账号资格与错误归因

查询当前官方支持地区和使用条款，而不是用出口地理标签替代实际资格。不提供换号规避封禁、伪装地区/设备或轮换标识规避限制的操作方案。明确账号限制应按官方通知与支持/申诉路径处理；正常退出错误登录、修复配置和清除用户自己的历史仍可按授权进行。

区分以下证据：

- `App unavailable in region`：地区/服务可用性错误，不等于已封禁。
- 401/403、OAuth callback 失败：可能是认证、权限、WAF、回调路径等，不能单凭代码确认封禁。
- `essential-traffic-only`：优先查功能开关，不是清历史或改 GitHub 授权的充分理由。
- 公网 IP 一样但城市不同：可能是地理数据库差异，记录各指标，不能据此断言异常登录。
- 明确停用通知：保留脱敏错误、时间和官方说明，按支持路径处理；不连续尝试换环境或新号。

住宅、静态、独享是不同属性，任何一个都不保证可用或账号安全。浏览器独立 profile 能隔离登录数据，不会自动配置网络，也不等于指纹浏览器。

只记录有依据的措施：官方说明、实际配置、实测请求、模拟结果、个人经验/未知分别标注。没有证据的“隐私开关防封”不设为默认；不为了追求检测网站全绿破坏用户需要的功能。

官方核验入口：[支持地区](https://support.claude.com/en/articles/8461763-where-can-i-access-claude)、[限制与申诉](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals)、[服务条款](https://www.anthropic.com/legal/consumer-terms)。具体政策以执行时最新说明为准，不在技能保存固定国家列表或猜测风控权重。
