# 公众号组件样式库契约

> 用途：连接 `wechat-medical-writer` 与独立 `image-gallery` 中的公众号组件库。这里记录**稳定样式 ID、选择规则和事实源边界**，不复制整套 CSS/HTML 实现。

## 1. 事实源

公众号样式库的可视化与可复制 inline HTML 由以下仓库维护：

```text
repo: https://github.com/sdwurg180507280211/image-gallery/
site: https://sdwurg180507280211.github.io/image-gallery/
source: wechat/index.html
```

主站与“人物图片 / 医药KV / 公众号”共享同一个首页一级 Tab；`wechat/` 作为组件数据与兼容入口保留。

本 Skill 不复制 image-gallery 中的完整 HTML/CSS。**如果样式展示与本文件文字描述不一致，以 image-gallery 当前 `wechat/index.html` 为视觉/复制实现事实源。**

## 3. 用户指定样式时的行为

用户可以直接给组合，例如：

```text
顶部关注-02 + 导语-01 + 标题-02 + 正文-02 + 图片-05 + 参考文献-01 + 结尾-01
```

此时：

1. 把这些 ID 当作明确的排版约束，而不是“灵感参考”；
2. 优先读取 image-gallery 当前组件实现并复用对应 inline HTML 语法；
3. 不擅自替换成另一个同类组件；
4. 不为了“丰富版式”额外堆叠大量未指定的大型组件；
5. 医学事实、引用和文章结构仍由上游 Writer 与医学约束决定，组件只负责呈现；
6. 图片 ID 的品牌资产边界同时遵守 `../brands/yihui-she-health.md`。

如果用户只指定部分 ID，例如只说“标题-02 + 参考文献-01”，其余部分采用最克制、最适合文章的基础正文，不把“未指定”解释成“把组件库全用一遍”。

## 4. 没有指定样式时

没有明确 ID 时，按以下优先级选择：

```text
用户点名参考文章 / 真实 HTML
> 用户明确描述的视觉偏好
> 医荟她健康品牌画像
> 组件库中的最小必要组合
```

High fidelity 仍然遵守“组件密度”原则：文章逻辑问题多，不等于每个问题都需要一个标题卡。

## 5. 复制 HTML 契约

image-gallery 每张组件卡的“复制 HTML”输出应是**可独立使用的 inline HTML**，而不是依赖站点 class 或外部 CSS 的片段。

因此生成整篇公众号 HTML 时：

- 可复用组件的 inline style 结构；
- 不把 image-gallery 的页面 UI 样式一起复制进文章；
- 不把来源分析、CSS 参数、出现次数等研究信息展示给最终读者；
- 图片组件使用正式公开图片 URL，避免 `YOUR_IMAGE_URL` 一类占位符进入成稿。


## 7. 更新原则

新增样式库能力时，优先更新 image-gallery 的组件实现，再同步本文件的 ID 注册表和 Skill 路由说明。

不要把用户提供的原始参考公众号 HTML、Logo、ZIP 或第三方品牌素材复制到本仓库；本仓库沉淀的是**可复用规则、组件语义和编排能力**。
