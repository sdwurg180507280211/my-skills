# 出口守护与 CLI 入口

本参考来自已遇到的故障和修复，不是安装脚本。本机已有实现时先读它的配置和启动入口；没有实现时先给方案，获得授权后再做。

## 架构

```text
专用 Chrome profile / 受保护的 CLI 入口
  → 本机出口守护（示例 17890）
  → Clash 专用 listener（示例 17891，见 clash-routing.md）
  → 普通前置 → 固定落地 → Claude
```

端口是示例。从实际 `guard-config.json` 读取 listen/upstream/期望 IP/落地节点名称。普通 TUN 流量和使用专用入口的流量是两个作用域。

## 出口守护

守护只连接约定的本机上游，不修改 Clash、不切换节点、不自动接受新 IP。已有实现的参数：后台每 20 秒复查；新连接距上次确认超过 10 秒先复查；确认最长有效 40 秒。维护时以现有配置为准。

- 两个独立探针中任一返回非期望 IP → 阻断。
- 两个都无法确认 → 阻断；一个确认期望 IP、另一个失败 → 放行并报告检测降级。
- 阻断时拒绝新连接并关闭已有隧道，确认恢复后放行。
- 同时校验上游 listener 的固定节点和前置关联，不只比较公网 IP。
- 只读状态页在阻断时也可访问，包含服务标识、版本、健康度、期望 IP 和检测结果。

这是周期检测，存在发现窗口，不是逐包校验或系统防火墙。绕过入口的应用不受保护。入口不监听时客户端应报错，不改用普通端口、TUN 或直连。

## CLI 入口

- 保留官方安装器维护的二进制，受保护入口单独命名（如 `claude-safe`），需要简写时用 shell function 调用它。用 `type claude` 确认当前 shell 实际调用的是哪一个。
- 入口启动或复用守护，就绪后再启动官方 CLI；子进程设置 HTTP/HTTPS/ALL_PROXY 大小写两套变量，`NO_PROXY` 只放 loopback，`BROWSER` 指向专用浏览器的 OAuth helper。
- 用户使用官方订阅时，入口为子进程移除继承来的 `ANTHROPIC_*` 和第三方 provider 变量；使用合法 API 的用户保留。
- 用 `--settings` 提高网络配置优先级时，说明它是否允许用户再追加 `--settings`。
- 浏览器和 CLI 共用守护：CLI 用租约文件（定期刷新修改时间）表明仍在使用，两者都退出后守护空闲超时停止。默认不装 LaunchAgent。入口要转发 SIGHUP，关闭终端时也能删除租约；守护检查时删除进程已不存在的租约。
- 守护地址、端口只写在 `guard-config.json`，入口和浏览器参数都从它读取。
- 代理变量有两层：`~/.claude/settings.json` 让直接运行的官方二进制和 App 内的 Claude Code 也走守护（守护未运行时失败而不是直连）；入口的 `--settings` 文件压过项目设置。两层值保持一致。
- Claude 会话里执行的命令（git、npm、curl）会继承这组代理变量，走固定出口。需要直连的目标（如国内服务）在命令里显式清空代理，大文件下载注意固定出口的带宽。

## OAuth 回调

已发生的故障：Chrome 只设 `--proxy-bypass-list=<-loopback>` 时，本机回调也被送进代理，CLI 仍在监听 `127.0.0.1:<临时端口>`，浏览器却显示 localhost 无法访问。修正为只放行字面 loopback：

```text
--proxy-bypass-list=<-loopback>;localhost;127.0.0.1;[::1]
```

设置了 `--host-resolver-rules=MAP * ~NOTFOUND` 时，同时 `EXCLUDE 127.0.0.1, EXCLUDE localhost`。

排查顺序：

1. 用 `lsof` 看 CLI 的临时 listener 是否还在，区分代理绕行、解析失败、进程退出和授权过期。不重放用户粘贴的 `code`/`state`。
2. 修正启动参数后完整退出专用 Chrome 实例再启动；开新窗口会复用旧进程，参数不生效。只退出专用实例，不动普通 Chrome。
3. 用临时 profile 和合成 `TEST_ONLY` 参数测试 localhost、127.0.0.1 回调，IPv6 loopback 按实际支持测试并记录。
4. 让用户重新发起官方登录，保持认证终端运行直到成功，再用 `claude auth status` 核对。

## 模型升级

通过受保护入口执行升级并观察下载。只为当前选择设置 `model`，不为换模型改 API 地址或代理。用禁用工具的最小请求验证，以返回结果中的模型 ID 为准。

## 恢复

按层保留上一份：Clash 扩展和链式选择、守护代码和配置、浏览器参数、CLI 设置、shell function。恢复只覆盖本次修改；停止守护时按确认的 PID 或路径，不按进程名批量结束。

记录哪些是实测、哪些是模拟、哪些未测。已做过的合成测试包括：出口不符阻断、探针部分失败、确认过期、已有隧道关闭、状态页可用、大响应完整转发、CLI 租约和回调绕过；它们不能代替 Claude App、IPv6、真实节点故障和 Clash 整体退出的实测。
