# 网络模式、出口与残留检查

## 用多个证据判断路径

| 证据 | 能说明什么 | 不能单独说明什么 |
|---|---|---|
| macOS `scutil --proxy` | 系统代理/PAC 状态 | TUN 是否接管、终端实际出口 |
| 当前内核与有效配置的 `tun.enable` | 客户端运行及配置意图 | 某个域名最后命中的线路 |
| `route -n get <目标IP>` | 当前目标 IP 的系统路由 | 所有目标都由同一 TUN 接管 |
| 本机代理端口可连接 | 某个入口存在 | 协议、固定出口、线路稳定性 |
| 连接记录中的规则及节点链 | 此次请求的实际分流 | 未执行请求或整个客户端退出后的行为 |
| 通过同一入口查询公网 IP | 此次请求的公网出口 | 其他浏览器、CLI、App 的路径或账号资格 |

如已安装本机的只读 TUN 检测器，可调用其真实路径；先确认它只读配置且脱敏。检测器缺失时使用上表检查，不为一次诊断安装新的代理或重写网络配置。

## 有界请求

下面地址和端口仅是例子。替换为用户目标及已读取的入口。`--proxy ''` 会消除 curl 的显式代理覆盖，仍然经过现有系统路由和 TUN，不是关闭 TUN。

```bash
# 普通目标：通过现有系统路由；状态码只证明这个请求的可达性。
curl -q --proxy '' --noproxy '*' --connect-timeout 5 --max-time 15 \
  -I https://api.github.com/

# 用户要求的专用入口：禁止继承 NO_PROXY 绕过。
curl -q --proxy http://127.0.0.1:17890 --noproxy '' \
  --connect-timeout 7 --max-time 20 https://api.ipify.org/
```

用至少两项独立来源交叉检查，例如 IPify、Cloudflare trace 和 IPinfo。域名如果落在不同规则组，结果可能不同；先统一被测入口，再比较结果。不要关闭 TLS 验证来换取“通过”。

对 Claude 可通过同一受保护入口请求 `https://claude.ai/cdn-cgi/trace`，与该入口的公网 IP 比较；这只证明 trace 请求路径，不是登录或模型调用验证。

## DNS / IPv6 / 浏览器

- DNS 泄漏是查询未经过约定通道；污染是解析结果被篡改，两者不是同义词。
- Extended DNS 检测与客户端 DNS 配置、浏览器安全 DNS、连接记录一起解释。解析器的国家不等于出口国家；任何国外解析器也不自动证明没有泄漏。
- IPv6 启用时实际测 IPv6 请求与分流，未测不能声称“不漏 IPv6”。IPv4 检测成功不足以涵盖它。
- WebRTC、QUIC、浏览器 DNS 和扩展可能形成额外路径。独立 profile 只隔离登录数据，不等于指纹浏览器或网络隔离。
- 检测网站可能同时请求直连探针和 Claude 域名；国内直连 IP 与 Claude 出口不同可能正是约定分流，不应为了“全部一致”改成全局海外代理。

## 代理与认证残留

检查系统代理、当前 shell、shell 启动文件、npm/yarn/pnpm、Git、Homebrew 和 Claude 的用户/项目/托管配置。先报告配置来源和键名，不直接运行 `env | grep` 或 `cat settings.json` 后把值贴进聊天；这些位置可能包含认证和代理密码。

特别区分：

- `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` 及小写形式：进程的代理入口。
- `NO_PROXY` / `no_proxy`：绕过入口的范围，专用客户端通常只保留必要的本机回调。
- `ANTHROPIC_BASE_URL`：API 服务地址，不是普通网络代理。
- API Key / Auth Token / OAuth 登录：不同认证来源；仅在用户要求恢复官方登录时处理相冲突的第三方配置，不能泛化为删除所有 `ANTHROPIC_*`。
- shell alias/function、原生二进制和 GUI 启动：可能是不同入口。记录哪些入口受保护，哪些未纳入。

不把“显式本地代理可被看到”断言成封禁依据；TUN 也不会令应用在所有层面都“看起来是美国电脑”。

## 大文件和安装

短请求成功不能证明 Git pack 或 CLI 二进制下载可靠。设置总超时、降低并发、观察 staging 文件大小或实际传输，限制重试。若专用出口下载慢，不自动切到另一个公网出口；改走普通入口需要符合用户任务约束。

一旦结果没有改善，不循环改系统代理、DNS 和环境变量。保留失败证据，区分连接/TLS/认证/权限/配额错误后再决定下一步。
