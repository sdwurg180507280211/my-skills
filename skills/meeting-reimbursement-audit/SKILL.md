# 会议核销资料审核

适用于用户提供的一场或多场会议资料目录。先采用本次用户明确的范围和规则；以下是已确认的默认口径，不是任何平台的通用合规政策。“只检测 Excel”时跳过截图与海报；“只查海报背景”时不重查参会明细、重合率或截图。仅在海报检查属于本次范围时启用海报规则。

## 参会明细口径

- 唯一时长依据是参会明细中的 **`在线时长（分钟）`**。单人在线时长 **≥20 分钟**计入合格人数；一场合格人数 **≥10 人**即人数达标。20 分钟、10 人都含等号。
- 不用首次进入/最后离开时间重新计算，不扣会前/会后时间，不按海报时间截断，不推测离线间隔，也不因时间字段矛盾否定已报告的在线时长。需要标示会议时间时采用参会明细中的时间，但它不参与时长资格计算。
- 除非用户另有要求，不排除工作人员、拜耳人员等记录，不额外要求截图可见人数达到 10 人。
- 例：10:00 开会，09:51 进入、10:26 离开，报告在线时长为 25 分钟，**按 25 分钟计入**。不要再说“包含多少会前时间无法确定”。
- 数字或明确的数字分钟文本可读；空白、非数字、公式和未明确单位属于数据待核实，不能当作 0、不能用进出时间补算。脚本不计算公式，也不把缓存结果当作已执行重算。
- 统计的是人而不是行。同场重复记录不能累加成两个人，也不能擅自把多行时长求和。重复记录时长冲突需核实，不任取最大值。

## 名单重合率

“报告重复率”在此指**参会人员名单重合率**，不是文档文字重复率。

1. 使用每场完整参会名单去重后的集合，包括在线不足 20 分钟者，而不是只用合格人数子集。检查全部 `n × (n − 1) / 2` 对会议。
2. 按用户确认的 **用户ID + 姓名**组合匹配：两者都相同才计为重复。只规范全半角和空白，ID保留大小写，`*`是字面字符而不是通配符。同名但ID不同不算重复；即使医院、科室也相同，仍不能替代ID匹配。医院与科室只用于展示或追溯，不参与匹配键。
3. 用户ID或姓名缺失时列为待核实，不能退回按“姓名 + 医院 + 科室”认定重复或静默当作没有重合。同ID但姓名冲突需单独核查，不直接判为重复，也不把冲突掩盖为已确认的零重合。这里判断的是报告记录重合，不根据脱敏姓名推断真实身份。
4. 对每一对显示共同人数 `C`、两场去重人数 `A/B`、`C/A` 和 `C/B`。**默认以两者较高值判断，即 `C/min(A,B)`**。这是沿用的、可由用户调整的分母约定；尚未被明确为平台规则，必须简短披露，不能冒充官方政策。用户明确其他口径时按其指定执行。
5. **超过 50% 才不合格，等于 50% 合格**。比较未四舍五入的比例，显示时可保留两位小数。

## 只读核对脚本

优先运行 [scripts/audit_reports.py](scripts/audit_reports.py)，避免重复手算。它只读取 `.xlsx`，JSON 写到标准输出，不修改原件、不自动生成报告文件、不访问网络、不检查截图或海报。

```bash
python3 -B <skill-dir>/scripts/audit_reports.py "/资料/会议批次目录"
```

- Python 3.10+，依赖见 [requirements.txt](requirements.txt)。优先使用本机已有或宿主提供的 Python/openpyxl；缺失时说明依赖，不静默联网安装。
- 目录模式默认递归发现 `*参会明细*.xlsx`，忽略 `~$` 锁文件；可用 `--pattern '*.xlsx'` 指定已核实的文件模式，或直接传入多个报告文件。先核对发现列表与会议目录，避免漏文件或同时纳入多个版本。
- 自动在前 30 行定位 `用户ID/姓名/在线时长（分钟）` 表头，不假定固定行号；医院与科室为可选展示列。优先使用 `参会报告` 工作表；表结构有歧义时用 `--sheet` 明确选择，不猜测。
- 输出包含原文件、工作表、表头行、源记录行、去重人数、确定合格人数、无法确定人数和所有会议对。`errors`、`data_issues` 和 `needs_review` 必须核查；不把读取失败当作审核通过。
- 时长未知时按已知合格人数和可能合格人数给出范围：下界 ≥10 可确认人数达标，上界 <10 可确认不足，其余待核实。这里的待核实只源于缺值或重复/身份问题，**不能重新引入会前时长不确定性**。
- 脚本支持 `--overlap-policy larger-ratio`（默认）和 `smaller-ratio`（仅当用户指定两场比例均超标才算超标）。其他分母必须在用户指定后单独明确计算；不要套用不等价开关。
- `.xls` 或不匹配的表头不受脚本支持。可换用合适的只读解析方法，但不改写原件、不隐瞒未审范围。

脚本是数据计算辅助，不自动决定整场最终合规：人数、重合率、截图与海报按本次范围分别检查。

## 截图与海报：选择复核方法

截图或海报在本次范围内时，有两种方法，**用户未指定就先问选哪一种**，不要自行决定：

- **方法一：模型看图审核**。按下文“两张截图”“海报背景”的口径由模型逐场看图判定。
- **方法二：网页人工复核**。生成一个本地 HTML，每场一行并排列出课前截图、课中截图、海报；用户自己在浏览器里看图、勾“有问题”、写备注，模型再读回标注并汇总。方法二**不做任何自动识别或判定**（不 OCR、不检测人脸/logo），检查标准以用户本次说的为准（例如讲者头像、logo、项目名），写在交付说明里即可。

用户说“我自己看”“列到网页里”“放到 html 上我去检查”时即为方法二；中途改主意，按新方法处理对应图片，不混用两种结论。

### 方法二步骤

1. 生成网页（zip 先解压到资料目录之外的临时目录，原件不改）：

   ```bash
   python3 -I -B <skill-dir>/scripts/build_review_html.py "/资料/会议批次目录" --out "/用户指定的输出目录/截图复核" --key 批次名
   ```

   - 批次目录下每个子目录算一场；递归找图片，路径含“课前/付费服务提供者照片”归课前截图，“课中/会场照片”归课中截图，“海报/议程”归海报，其余放“其他图片”列。缺的项在页面标红“未找到X”，同时出现在输出 JSON 的 `missing` 中，单列为材料缺失。
   - 输出目录不能放在批次目录内（脚本会拒绝）；由用户指定或放在资料目录旁边，不进技能目录。
   - `--key` 是浏览器保存标注的键前缀（默认取输出目录名）。同一批次重新生成时用同一个 key，已有标注会保留；不同批次用不同 key，避免互相串。
   - 生成后用 `open` 打开或把路径给用户；告诉用户：点图放大，勾“有问题”并写备注，标注自动存浏览器，也可点“导出有问题场次 CSV”。

2. 用户说标完后读回：

   ```bash
   python3 -I -B <skill-dir>/scripts/read_review_notes.py --key 批次名
   python3 -I -B <skill-dir>/scripts/read_review_notes.py --csv ~/Downloads/截图复核结果.csv
   ```

   - 用户导出了 CSV 就优先读 CSV。否则用 `--key` 只读解析 Chrome 各 Profile 的 `Local Storage/leveldb/*.log`，不修改浏览器数据。
   - 退出码 2 / `sources` 为空表示没读到：可能不是 Chrome，或标注已被 Chrome 压缩进 `.ldb`。这时请用户点“导出”后用 `--csv` 读取，**不能当作“无问题”**。
   - 只输出勾了“有问题”或写了备注的场次；只写了备注未勾选的，按备注内容如实列出并注明“未勾选”，不擅自定性。

3. 交付：按“结论交付”的截图/海报表格列出用户标注的场次，“具体问题”填用户备注原文（可按截图/海报归入对应表），并附网页路径。不对用户已判合格的场次追加模型意见；用户要求时才另行看图。

## 两张截图

通常分别检查课前与课中截图，例如 `付费服务提供者照片/截屏-课前.jpg`、`会场照片/截屏-课中.jpg`；实际以用户目录为准，不依赖固定会议日期或裁剪坐标。

- 默认只判断**截图里有没有参会头像或人像画面**。有头像即合格，不再要求正脸、完整五官或无遮挡；侧脸、偏头、闭眼、姓名栏/手部遮挡、视频框裁切，只要仍能辨认出头像或人像画面，都不作为不合格理由。
- 默认头像、灰色人形占位头像也按“有头像”处理，不额外要求真人视频或确认讲者身份。只有讲话姓名、话筒图标或课件中的医学插画/人物示意图，不算参会头像。
- **只有背景、课件或共享屏幕，没有任何参会头像/人像画面，才判截图不合格。** 不根据小视频框、下半脸不完整或脸部低清追加问题。
- 批量任务先快速浏览原图或可辨识的拼图；能确认有头像的直接通过，无需逐张裁剪、放大或检查五官。疑似没有头像的候选再查看整张原图，检查角落、侧栏和上下方，不能固定只看右上角或仅凭局部裁剪认定缺失。只有确实无法判断头像是否存在时才放大；临时预览不进入技能仓库，不替代原件。
- 图片打不开，或整体画质使“是否有头像”都无法判断时，单列待核实，不能冒充没有头像。仅嘴部/遮挡细节不清，不列为待核实。
- 如用户明确要求指定讲者，按文件角色和文字标签定位，不根据脸确认身份；其他更严格的截图要求只在用户当次明确提出时启用。
- 没有要求时不扩展为截图重复检测、拍摄日期审核、会议时间比对或图片真实性鉴定。禁止生成/修脸/补脸以替代审核证据。

## 海报背景

只检查背景是否透明、缺失或明显异常，不检查文字、会议时间、头像、二维码或讲者身份，也不将海报时间用于参会资格计算。

- 先按会议目录查找海报，例如 `最终会议议程-海报.jpg`；名称和扩展名以实际文件为准，不能把课前/课中截图当作海报。同一批次有不同设计时，分别参考同类正常海报，不固定颜色、装饰图案或画布尺寸。
- 批量先快速浏览原图或可辨识的拼图，确认主体背景正常的直接通过。仅对疑似透明、缺背景或截断的候选回看整张原图并与同类正常海报对照，不逐张做文字识别或头像审查。
- **主体背景透明、应有背景消失，或画面截断导致背景明显不完整**，才列为确定背景问题。若只剩正常海报的一小段且主要背景画面丢失，写“画面截断／背景明显不完整”，不要误写成“透明背景”。尺寸或长宽比异常只能帮助定位候选，不能单独作为不合格依据。
- **透明边缘、圆角或底部空白条不等于主体背景缺失**。主体设计完整时不因这些留白判不合格；白色、浅色、纯色背景或其他正常模板也不因缺少复杂装饰判不合格。
- 需要确认透明时，按实际图片格式读取透明通道，必要时在临时预览中用棋盘格或不同底色辅助辨别。`.jpg` 文件也可能实际为 PNG；有 RGBA 通道或存在少量透明像素本身不构成问题。结合透明区域的位置和原图判断，不能用透明像素占比直接判定。
- 没找到海报时核对该会议目录内的文件，再单列“海报文件缺失，背景无法核验”；图片打不开或无法判断背景时列为待核实。两者都不混入确定背景不合格项，不把未检查写成合格。
- 原件保持不变，拼图与透明度预览只写到临时目录；不补背景、不改图、不生成替代海报，也不把真实海报或当次结果保存进技能仓库。

## 结论交付

默认只总结确定不合格项，不展开正常会议清单。按本次检查范围，将参会明细、截图与海报背景问题分别列成 Markdown 表格；只查一类时仅输出该类。先给结果，再用一句话说明必要的判定口径。

**表一：参会明细问题**

| 会议 / 会议组合 | 问题 | 核对依据 |
| --- | --- | --- |

人数不足写“在线时长 ≥20 分钟的去重人数为 X，低于 10 人”；重合超标写“共同 C 人，C/A 与 C/B，按已披露口径超过 50%”，并提供原文件/工作表/行号等可追溯依据。

**表二：截图问题**

| 会议 | 截图 | 具体问题 |
| --- | --- | --- |

明确写课前、课中或两张，问题写“只有课件/背景，没有头像”，并链接原图；不要把侧脸、遮挡或裁切列为问题。

**表三：海报背景问题**

| 会议 | 海报 | 具体背景问题 |
| --- | --- | --- |

写明主体背景透明、缺失或画面截断的实际情况，并链接原图；不列文字或头像问题。海报文件缺失单独说明“材料缺失，背景无法核验”，不混入背景不合格表。

对应检查无问题时写“未发现确定不合格项”，不填合格会议凑表。按要求跳过的项目可简短说明“未检查”，不能说其合格；不输出未检查类别的空表。

补充约束：

- 个别人的在线时长 <20 分钟，不代表整场不合格；若其余合格人数 ≥10，不列为人数不足。
- 待核实项不能混入确定不合格表。如影响结论，用简短独立说明列出具体缺值/图像限制，不展开正常项，也不含糊地说“不再判定为确定人数不足”。
- 更正规则后，按新口径重查受影响的项目并撤销旧结论；时长/人数口径变化覆盖全部会议，重合口径变化覆盖全部配对，截图或海报口径变化只复核对应图片。不要保留已经失效的海报时间、会前扣减或正脸/遮挡诊断，也不重做用户已排除的检查。
- 默认只在会话中给结论，不新建 Excel、不编辑参会报告、不移动原件、不自动上传网站。用户另行明确要求修改/上传时才进入对应操作；审核本身不构成该授权。
- 真实名单、截图、海报、会议报告、内部平台链接和当次结果不得复制进技能目录。测试使用合成记录。
