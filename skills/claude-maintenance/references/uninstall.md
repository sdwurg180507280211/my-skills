# 完整卸载 Claude

用于删除 Claude 软件及残留。仅清缓存、修认证或保留程序可用性时，使用 cleanup-and-recovery.md。

## 安装来源与影响清单

分别检查命令入口、实际目标、包管理器记录和后台入口；一次 PATH 查询不能排除并存安装。

- 原生安装：启动链接通常位于 `~/.local/bin/claude`，版本目录在 `~/.local/share/claude`。自定义包装可能替代原启动链接。
- npm：遍历实际存在的 nvm 各 Node 前缀和其他全局前缀。用对应 Node 执行该前缀 npm-cli.js，显式指定 `--prefix` 卸载；当前默认 npm 可能看不到旧版本安装。保留共用 Node/npm/nvm。
- Homebrew、Windows 安装器及 IDE 扩展：按已发现的安装来源卸载，不无条件运行所有卸载命令。
- 桌面版、专用浏览器启动器、URL handler、shell function/alias、守护、登录项和定时器独立盘点。专用浏览器实际可能使用 Chrome Beta；按真实 user-data-dir 识别，保留共用浏览器程序。
- 配置、会话、任务、缓存、MCP 专用环境、桌面应用存储、精确钥匙串服务、共用配置管理器及其历史备份分开列明。

仅搜索已知路径和文件名不足以认定整机安全。报告覆盖位置、权限错误和未检查范围；企业通知中的风险描述不自动等于本机取证结论。

## 承接授权

用户已审阅具体清单并允许直接删除时，执行清单范围，无需反复确认。对已明确包含的配置、历史、专用浏览器资料和精确凭据服务沿用同一授权。永久删除与废纸篓隔离如实区分；用户要求不得留存时，不额外保留可运行程序、会话或令牌全量备份。

云端授权撤销、组织策略、共用凭据轮换和整盘清除不由本机卸载自动授权。系统管理员认证是操作系统权限步骤，不能通过改名隐藏失败或扩大删除范围绕过。

## 删除前保护业务数据

`jobs` 不是纯缓存：任务临时目录可能保存 PPT、文档、图片等正式成果。按用户已确认的数据范围保存所需成品到普通业务位置，校验副本后处理运行数据；避免把整个任务树、账号信息或代码执行环境作为“成果”备份。状态写着 working 不等于进程仍活着，结合进程、更新时间及文件占用判断。

识别全局和项目 `.claude` 中的 Git worktree。检查未提交、未跟踪和未推送工作；按用户已确认的数据范围保留、迁移或删除。已明确授权删除该 worktree 及其工作内容时，不另行要求备份或确认。使用 Git 管理对应注册元数据，保留主仓库与不相关分支。

技能软链接只删除链接本身；以目标真实路径建立保护边界，递归删除不跟随目录链接。`CLAUDE.md`、第三方依赖中的同名文件、用户业务源码不是已安装软件，分别判断。

## 分层执行

1. 用一次进程快照筛选候选，再核对少量 PID 的真实可执行文件及专用 profile。退出已确认的专用实例，避免循环对所有系统进程逐一查询或批量杀掉 Chrome/Python。
2. 按来源卸载全部已发现安装，处理包装、快捷方式和 shell 完整定义；修改 shell 后检查语法。
3. npm 返回成功也要看 cleanup 警告。它可能把包改名为 `@anthropic-ai/.claude-code-*` 后因旧文件属主为 root 留下完整程序。只复查该前缀下已核实的残留；管理员操作只针对残留，保留 Node 根目录。
4. 清理经授权的专用数据，分别删除精确钥匙串服务，不读取密码值。受禁/可疑程序不重新启动做 logout 或版本测试，服务端撤销另行处理。
5. 共用配置管理器按应用类型清理 Claude provider、prompt、MCP/skill 启用标记、代理接管备份及历史数据库；保留其他客户端记录。修改 SQLite 时先确认无并发写入，按实际 schema 处理，清除历史副本中的对应敏感项而非整库删除。安全删除与压缩不代表 SSD/快照中所有历史块已物理擦除。
6. 网络配置只处理已证实独占的规则/listener；共享 Clash/TUN、节点和其他客户端链路保持。保留会影响其他业务的共用条目并在结果中说明。

## 防止重建和验收

技能同步必须显式指定仍在使用的目标。若仓库脚本默认向 Claude、Codex 和 WorkBuddy 同步，卸载 Claude 后调用其目标选择参数，只同步保留客户端；不要为完成“技能沉淀”重新创建 `.claude/skills`。在交付说明中注明以后默认同步可能重建目录，需要保留该目标选择。

卸载验收检查所有列出的安装、包装、数据、凭据及自启动；新 shell 不再解析到 CLI/别名，正常编辑器不会重新生成目录。以路径和存在性检查验收，不重新运行受禁程序。维护清理的“程序仍可启动、认证成功”不适用于卸载。

分别报告：已永久删除、保留的业务成果、保留的共用组件、权限阻塞、云端待办和未覆盖的备份/快照。移入废纸篓、包管理器退出码 0、删掉一个链接都不能单独作为“彻底删除”的证据。

## 指定文件命中

如需排查 `router_runtime.js` 或 `setup.mjs`，记录路径、哈希、源码用途与 hooks/任务调用关系。`setup.mjs` 也是正常 SDK 下载或依赖手势模块的文件名，不能按名字全盘删除。分两轮扫描：先检查控制配置与持久化入口，再按需要覆盖依赖目录；不跟随技能链接，也不向公开服务上传用户配置或文件原文。

## 公共方案的使用

[官方卸载路径](https://code.claude.com/docs/en/setup#uninstall-claude-code)用于核对来源。第三方脚本只在审阅实际下载内容与依赖后使用：原生 CLI 脚本可能漏掉 npm、`.claude.json`、钥匙串；Desktop 脚本可能刻意保留 CLI；自动备份可能违背不得留存要求。保存审阅版本/哈希，不以 README 声称的“完全删除”替代本机验收。
