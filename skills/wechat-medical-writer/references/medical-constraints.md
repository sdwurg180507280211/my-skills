# Medical Constraints

本文件只补充通用 Writer 通常不具备的医学事实边界，不规定文章结构或写作方法。

## 1. 资料角色要分清

- 用户上传的医学 ZIP/PPT 可以用于定义长期内容方向，也可以在用户明确要求时作为某篇文章的资料来源。
- 领域资料不自动等于唯一事实来源。
- 用户提供的公众号样稿可以作为结构、语气、信息密度和完成度参考，但样稿中的数字、指南结论和参考文献不能因为“出现在样稿里”就视为已核验。
- 产品课件、内部培训材料和营销材料不能单独证明适应证、优越性、监管状态或绝对化结论。

## 2. 不虚构医学来源

不得虚构或补造：

- 指南 / 共识名称、年份、推荐等级；
- 论文作者、期刊、DOI、PMID、样本量、终点、统计量；
- NMPA / FDA / EMA 等监管状态；
- 说明书、注册证、适应证、禁忌证；
- 疗效、安全性、风险、患病率或保护效力数字。

来源不足时，明确说明“当前资料不足以支持该结论”。

## 3. 面向公开发布的医学文章默认需要可核验来源

不要把“用户没有明确说研究/核验”理解成“可以不核验”。只要目标是形成可公开发布的医学公众号/服务号文章，正文中以下内容默认都应能回到可追溯来源：

- 具体比例、样本量、OR / RR / HR / P 值、时间点等数字；
- 指南 / 共识推荐及适用人群；
- 疗效、安全性、不良事件、疾病进展或自然史结论；
- 适应证、禁忌证、用法流程、注册 / 批准状态；
- “更高、更低、优于、增加、降低”等比较性结论；
- 可能影响临床决策的关键医学事实。

优先使用与问题直接相关的原始或权威来源，例如：

- 官方指南 / 专业学会指南与共识；
- 药品说明书、医疗器械注册资料、监管机构资料；
- 原始临床研究、系统评价 / Meta 分析；
- WHO、IARC、国家卫生健康部门等权威机构资料。

如果用户明确要求“只根据我提供的资料写，不做外部核验”，可以只使用用户资料，但最终稿必须清楚说明相关事实**仅依据用户提供资料，未完成外部独立核验**。不要把这种模式默认为普通医学文章的默认状态。

具体检索、研究笔记、大纲和引用格式仍由主 Writer 的原生流程决定，本 Skill 不另起一套 research workflow。

引用指南时核对发布机构、版本、适用地区与人群；不同指南存在分歧时说明差异，不拼成统一推荐。引用二手报道中的关键数字时回溯原研究，无法读取原文就说明核验范围。区分获批适应证、研究中用途和临床常规，尤其不把 PDT/HAL-PDT 的研究结果直接写成普遍推荐。

## 4. 成稿前做引用完整性检查

不要求额外生成 Claim Ledger，但公开稿输出前必须检查正文与参考文献是否闭环：

- 正文出现的 `[n]` / 脚注 / 作者年份引用，在参考文献列表中必须存在；
- 参考文献列表中的条目应确实支撑正文内容，避免大量未使用的“装饰性参考文献”；
- 每个具体医学数字都应能定位到相应来源及其人群 / 时间点 / 研究设计；
- DOI、PMID、作者、年份、期刊、卷期页码不得凭记忆补齐；拿不准就查原始来源或删除该字段；
- 同一来源在正文中的编号保持一致；
- 若来源只能支持“相关/提示”，不得写成“证实/导致/必然”。

发现引用缺口时先修正再交付，不要在正文已经完成后只加一句泛化免责声明来掩盖证据缺口。

## 5. 医学配图和数据图约束

当文章继续交给 `canghe-article-illustrator` 或其他配图工具时，医学事实边界继续生效：

### 数据图 / 信息图

- 只能使用正文中已经核验、已有来源的数据；
- 禁止为了让图更完整而让模型补造数字、比例、时间点或比较关系；
- 图注中保留对应参考文献编号或数据来源；
- 论文原图默认不要直接截图搬运，优先在版权允许和数据可获得的前提下依据已核验数据重新绘制。

### 机制图 / 流程图

- 可以重新设计医学概念和流程示意；
- 不得把假说、相关性或机制推测画成已经证实的确定因果链；
- 图中新增的医学标签同样需要与正文和来源一致。

### 产品 / 器械 / 包装

- 优先使用用户提供的官方批准素材或品牌资产；
- 不让生成模型虚构真实药品包装、医疗器械结构、批准标识或产品外观并冒充官方素材。

## 6. 不把表达优化变成事实改写

如果后续使用 Viral Writer 或其他表达优化 Skill：

- 可以优化标题、开头、节奏、段落和可读性；
- 不得为了“更抓人”把“可能、相关、提示”改成“必然、证实、导致”；
- 不得新增恐惧性医学结论；
- 不得改动医学数字、适用人群、时间范围、统计结论和引用关系；
- 不得自行加入“唯一、首个、最安全、最有效、无痛、无创、治愈”等结论。

## 7. 不强加额外产物

除非用户明确要求，不强制生成：

- Claim Ledger；
- source-map；
- 固定审核表；
- 固定工作目录；
- 固定医生端 / 患者端模板；
- 固定篇幅和章节数量。

文章如何组织，由用户当前要求、参考样稿和主 Writer 的成熟流程共同决定。
