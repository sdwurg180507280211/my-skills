# 医荟她健康医学公众号适配层

保留现有名称。这里维护医学与品牌特有的约束，上游负责研究写作、普通配图、HTML 排版和微信发布。目标是稳定复用用户已认可的文章观感，不固定文章结构、章节数、图数或输出文件集合。

## 加载上下文

- 医学写作或事实编辑：读取 [女性全生命周期领域](references/domains/womens-lifecycle.md) 和 [医学约束](references/medical-constraints.md)；主题属于 HPV、宫颈癌筛查或宫颈病变时，再读 [宫颈健康细分](references/domains/cervical-health.md)。ZIP/PPT 定义内容方向或提供当次来源，不定义写作模板。
- 需要公众号成品、封面或配图时：先读取 [Image Gallery 风格方案接口](references/layouts/image-gallery-styles.md)。用户给出固定链接时读取该快照，不能用当前默认覆盖；没有指定方案时才读库默认。将排版、封面、正文三个案例传给对应流程，保留正文所选案例的整体设计，不自行拆分画风和布局。
- 医荟她成品：读取 [品牌画像](references/brands/yihui-she-health.md)。已有文章仅排版时保留正文事实与引用。
- HTML 排版：读取 [医荟她文章样式](references/layouts/yihui-article-style.md)，默认采用用户喜欢的 HPV 长文的字体、克制标题和科学图节奏；遵守其中的段落疏密与参考文献内部滚动偏好。用户指定样稿时按样稿核对组件及行为，不能把基础 CSS 当作完整复刻。
- 原始医学资料、样本 HTML、图片和运行时文章留在用户工作目录，不提交公共仓库。

用户当次明确要求 > 指定快照或网页已保存的本次选择 > 网页当前默认 > 本技能原有默认。风格方案只改变视觉与排版，不改变医学证据约束。其他账号不能自动继承医荟她 Logo、品牌名称或渠道能力。

## 写作交给现成 Writer

需要从主题研究成稿时，先读 [上游与安装](references/upstreams.md)，检查所选 Writer 的真实路径并完整读取其 `SKILL.md`，再按其原生流程执行。写出 Skill 名称不等于已经加载或调用。

`content-research-writer` 是当前可用默认候选，尚未通过医学中文长文对照评测，不是已验证的唯一最佳 Writer。用户指定其他成熟 Writer 时使用其原生流程；不自行创建 fallback Writer，不改写 vendored 上游。

传递已知的主题、受众（患者/公众或医生/HCP）、目标、篇幅、私有来源、参考样稿、领域与医学约束。已有信息不重复问；用户要求一口气成稿时连续执行上游流程，不人为设置逐节确认。

医学结论、关键数字、适应证和指南推荐必须能回到实际来源。样稿只能证明用户偏好的表达和观感，不能证明其中医学事实正确。资料不足时缩小结论或明确缺口。

不需要第二个 Writer 作为默认步骤。用户要求传播表达优化时才加载已安装的表达 Skill，保持数字、医学结论和引用关系不变。评测候选的比较标准见上游文档；未实测不得宣称某候选获胜。

## 按交付目标加载下游

| 当次需要 | 复用能力 / 附加上下文 |
|---|---|
| 普通概念插图 | `canghe-article-illustrator`，叠加医学约束 |
| 统计图、多面板科学图 | [医学 Figure 约束](references/medical-figure-design.md)，用可控绘图工具锁定数据与文字 |
| 常规公众号 HTML | `canghe-markdown-to-html`，按医荟她文章样式中的已验证入口加载外部 `yihui.css`；方案有明确 CSS 时追加其视觉覆盖并内联化，组件按方案实际定义插入 |
| 用户指定样式 ID | [组件库外部接口](references/layouts/wechat-component-library.md)，按实际版本取组件 |
| 医荟她读者问答稿 | `scripts/render_yihui.py` 识别 `**读者问：**` / `**医荟她答：**` 段落，自动改用图库 `layout-yihui-interview`；回答一方署名医荟她健康，不虚构专家或访谈 |
| 访谈 / Q&A 复杂布局 | 外部 `xiaohu-wechat-format`，仅用 formatter |
| 明确要求光愈式头像访谈 | [光愈参考](references/layouts/guangyu-online.md)；上游缺头像时才用现有窄适配器，使用医荟她与真实专家素材 |
| 上传微信草稿 | `canghe-post-to-wechat`，先执行下述发布检查 |

纯写作不需要排版或发布依赖。已有成稿只需排版时，不强制重新研究或重写全文。缺少所需上游时说明具体安装方法；已完成部分正常交付，不用自制实现替代依赖。

科学图遵循“借复杂度，不借内容；借版式，不借证据”。图片随对应证据和论证放置，不按页面百分比插入；不要为均匀分图改变医学含义。

## 成品与发布检查

交付前按已读取方案检查三类风格；未被方案覆盖的项目按 [医荟她样式基准](references/layouts/yihui-article-style.md) 检查字体、图文衔接、引用和品牌。封面默认 2.35:1。微信有独立标题字段，正文不重复放文章 H1。

发布前完整读取已安装发布器的说明与适用图片输入方式。审计版本的限制和证据见 [上游文档](references/upstreams.md#发布器已知限制)。

- 默认交付 Markdown / HTML；用户要求上传时才创建草稿，创建草稿不等于群发。医学号与技术号使用独立项目配置，上传前核对目标身份；缺配置时不回退其他账号。
- 优先把生成图保存为本地 PNG/JPEG，并用发布器支持的路径引用。不要把 base64 内嵌 HTML 直接交给不支持 data URI 的 API 路径。
- 明确指定符合品牌比例的封面；不要让发布器自动把第一张多面板科学图用作封面。
- 如果用户给的是内嵌图 HTML，优先使用上游已支持的转换；没有时报告这一输入限制，保留成稿，不能把图片缺失的上传称为成功。
- 上传日志出现图片失败时，不以“创建草稿成功”作为整篇成功；检查草稿中的每张正文图和封面，并报告失败项。不要为重试盲目创建重复草稿。
- 图片来源地址与最终微信托管地址分开看待。API 发布读回同账号草稿，核对正文图数量、顺序、素材映射和独立封面；微信可能返回 `data-src` 懒加载属性，不只检查 `src`。具体已验证行为见 [草稿读回与重复交付](references/upstreams.md#草稿读回与重复交付)。浏览器发布检查实际草稿中的图片完整性。
- 最终核对移动端观感、参考文献条目与滚动行为、无光愈品牌残留。区分本地手机宽度预览、微信返回内容核验与真实微信客户端预览，不把前两者称为已完成客户端验收。草稿是交付点，不是医学审稿通过；正式发布前仍需用户或专业人员通读正文、核图与引用。

不强制 Claim Ledger、source map、固定审核文件或患者/医生文章模板。保留必要医学约束、真实品牌参数和已证实的依赖限制即可。
